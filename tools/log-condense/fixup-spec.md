# 로그 통폐합 — 보완 라운드 스펙 (정정 기록 복원)

리포 `/Users/hckim/repo/rig-log`. 앞 라운드가 날짜 파일 `log/2026-09-DD.md`를 만들었다(옛 실험별 파일 `log/2026-09-DD-*.md`를 합치고 약 20%로 축약). 앞 라운드 공통 스펙은 `/Users/hckim/repo/rig-log/tools/log-condense/condense-spec.md` — 먼저 읽어라. 그 규칙은 전부 유효하다.

이 라운드는 **네 날짜 파일 하나만 고친다.** 새로 쓰지 말고 기존 파일을 편집한다.

## 왜

이 리포에서 `~~취소선~~`은 "원래 저자가 이렇게 썼다가 나중에 그었다"는 **이력 기록**이다. 틀리면 지우지 않고 선을 긋는 것이 리포의 규율이다. 앞 라운드는 세 가지로 이걸 훼손했다:

1. 원문의 취소선 정정을 뺐다.
2. 원문 취소선 문장을 다른 말로 바꿔 적었다(이력 조작).
3. 원문에 취소선이 없던 곳에 취소선을 새로 만들었다(산문 정정이나 `**Struck**:` 표기를 `~~`로 바꾼 것 포함). 없던 취소선은 저자가 쓰지 않은 과거를 만든다.

## 할 일

1. 게이트를 돌려 FAIL 목록을 본다(게이트가 강화됐다):
   ```
   cd /Users/hckim/repo/rig-log
   python3 /Users/hckim/repo/rig-log/tools/log-condense/check-condense.py log/2026-09-DD.md log/2026-09-DD-*.md
   ```
2. **원문 취소선 복원**: 옛 파일의 `~~…~~` 구간을 **글자 그대로** 새 파일의 해당 절에 넣는다. 취소선 바로 뒤에는 원문의 정정문(무엇으로 바뀌었나)을 짧게 붙인다 — 정정문은 축약해도 되지만 취소선 안쪽은 한 글자도 바꾸지 않는다. 원문 취소선이 표 셀 안에 있었으면 표를 되살리지 말고 산문 한 문장 안에 그 구간을 넣어도 된다.
3. **없던 취소선 제거**: 게이트가 "strikethrough not in any old file"로 잡은 것은 `~~`를 없앤다. 원문이 산문으로 정정했으면 산문으로(예: "처음엔 X로 읽었는데 틀렸다 — Y였다"), 원문이 `**Struck**:` 같은 표기를 썼으면 그 표기 그대로 쓴다.
4. 분량 상한이 22%로 올랐다(복원분 몫). 복원 때문에 넘치면 다른 곳을 줄여서 맞춘다 — 정정 기록을 다시 빼는 것으로 맞추지 않는다.
5. 아래 "네 날짜 추가 지시"가 있으면 함께 처리한다.

완료 조건: 게이트 `PASS`. 게이트 스크립트 수정 금지.

# log-condense

실험별 로그 파일을 날짜 파일 하나로 합칠 때 쓰는 게이트와 링크 변환기. 2026-09-22에 09-11–09-21을 합치며 만들었다([기록](../../log/moved.tsv), 커밋 `ea2f343`).

- `check-condense.py <새 날짜 파일> <옛 파일...>` — 새 파일의 모든 숫자가 옛 파일에 있는지, 옛 파일마다 `<a name="<slug>"></a>`와 `원본: git show <커밋>:log/<옛 파일>` 줄이 있는지, 옛 `~~취소선~~`이 글자 그대로 남고 새 취소선이 없는지, 업스트림 URL·상대 링크, 분량 상한을 잰다. 환경변수 `CONDENSE_SRC_COMMIT`(옛 파일이 살아 있는 커밋), `CONDENSE_CAP`(기본 0.22).
- `relink.py <map.tsv> [--apply]` — 리포 전체의 옛 파일명 링크를 `2026-MM-DD.md#<slug>`로 바꾼다. 기본은 dry run. `configs/`는 기계 원본 그대로 두는 규칙이라 건드리지 않는다.
- `condense-spec.md`, `fixup-spec.md` — 위임 라운드에 준 스펙. 다음 날짜에 쓸 때는 날짜와 커밋만 바꾼다.
- `check-day.sh <새 파일> <YYYY-MM-DD> [원본 커밋]` — 날짜 파일 하나를 제자리에서 줄인 결과를 잰다(2026-09-30, 09-23–09-29에 썼다). check-condense(옛 앵커 전부 유지, 상한 0.45)와 check-log 절 규칙을 차례로 돌고 절마다 바이트·제목 길이를 찍는다.
- `inplace-spec.md` — 그 제자리 축약 라운드에 준 스펙. 한도는 절 2,500 B·제목 60자·파일 45 %이고, 같은 주제의 연속 절은 앵커를 쌓아 합친다. 결과 09-23–09-29는 387 KB → 164 KB, 절 129 → 106.

막는 실패 모드(실측): 첫 게이트는 "취소선이 하나라도 있나"만 재서, 원문 정정을 빼거나 바꿔 쓰거나 없던 취소선을 만든 파일이 전부 통과했다. 게이트는 숫자가 **있는지**만 보고 숫자에 붙은 **조건**은 못 본다 — 요약 문단이 서로 다른 카드·실행의 숫자를 섞는 것은 사람이 읽어서 잡았다.

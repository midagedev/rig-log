# Spark 작은 방 영상 — 디자인

1080×1080, 60 fps, 55 s. 내용 계약은 리드의 스펙(sparkclip)이다. 이 문서는 그 계약을 어떤 모양과 움직임으로 옮겼는지 적는다.

## 방향: 평면, 활자, 한 가지 신호색

2026년식 모션 그래픽이다. 평면에 활자를 중심에 두고, 3D 도 레트로도 아니다(사용자의 스타일 메모). 배경은 하나의 어두운 면이고, 카메라 비행 대신 같은 화면 안에서 요소가 들고 난다. 색의 뜻은 영상 처음 10 초 안에 배운다.

- **ember(주황)** 는 bloomery 의 답이다. Spark 팔, 링크, 패킷, 결과 숫자에 쓴다.
- **steel(차가운 회청)** 은 "그 전" 이다. 단독 팔, NVMe, 넘치는 바이트에 쓴다.
- **core(흰 열)** 는 가장 뜨거운 것이다. 카드 VRAM 의 expert 에 쓴다.
- **bone** 은 읽는 글, **ash** 는 캡션과 조건이다.

HOW 장면은 다이어그램 하나가 이어진다. 40층 띠와 라우터 격자, 세 집이 같은 화면에 있고 칸들이 격자에서 집으로 날아간다. 장면마다 새 그림을 띄우지 않는다.

그레인(초당 12번 바뀌는 256 px 타일, 알파 0.028)과 비녜트(모서리 −42 %)만 얹는다. 블룸, 피사계 심도, 광선은 쓰지 않는다. `--disable-gpu` 소프트웨어 래스터에서 프레임당 ~60 ms 를 지키기 위해서다.

## 활자

- 제목: **Geist** 620, 48 px. 장면 제목은 글리프마다 마스크에서 올라온다(0.42 s expo-out, 18 ms 간격). 나갈 때는 마스크 위로 빠진다.
- 숫자: **Geist Mono** 300. 경주의 tok/s 는 78 px, 결과의 1.8×·3.6× 는 150 px 이다. 자간 −6/−10 px 이고 자릿수 폭이 같다.
- 한글: **Pretendard** Medium. 토큰 스택은 `Geist, Pretendard` 다. 라틴은 Geist 로, 한글은 Pretendard 로 그린다. 시스템 글꼴로 빠지면 `render.py audit` 이 잡는다.
- 크기 바닥: 창의 토큰 28 px(스펙 바닥 22 px), 라벨·캡션 22 px 이상, 조건 줄 22 px.
- 숫자는 세지 않는다(count-up 없음). 모든 숫자는 `data.json` 에 있는 값으로만 나타나고, 들어올 때는 올라오거나 닦이듯 나온다.

## 움직임

- 이징은 도착에 expo-out, 이동에 cubic in-out 을 쓴다. 솟는 기둥과 상자는 감쇠 스프링(ζ 0.55, 4.2 Hz)으로 움직이고 넘침은 4 % 이하다.
- 아무것도 튀지 않는다. 모든 요소는 이동, 닦기, ≥ 0.3 s 페이드로 들고 난다. 예외는 경주의 토큰과 tok/s 다. 테이프 스탬프에 나타나는 계단이고, 그것이 내용이다.
- 장면 사이는 0.4–0.5 s 페이드에 위로 40–60 px 미끄러짐이고, 겹침은 0.1–0.2 s 다.
- 모션 블러는 `render.py full` 의 서브프레임(SUB 6) 평균이다.

## 장면별 배치

**HOOK.** 바닥선 y 905, 2.15 px/GB. 기둥(324 GB, 697 px)은 36조각이 바닥부터 스프링으로 쌓인다. 조각은 층이 아니라 바이트 덩어리다. 유리 상자(128 GB, 275 px)가 1.25 s 에 서고 2.35 s 에 기둥으로 미끄러진다. 3.1 s 부터 상자 위로 삐져나온 부분이 steel 빗금과 점선 테두리가 된다. 3.35 s 에 "It does not fit." 가 오른쪽에 뜬다.

**RACE.** 두 창은 488 px 폭에 간격 24 px 다. 창마다 다음이 있다.
- 머리: `128 GB workstation` 과 부제(`alone · experts from NVMe`, `+ one DGX Spark`).
- tok/s 카운터.
- 토큰 창: 440 px 높이, 줄 40 px. 새 줄이 오면 0.2 s smoothstep 으로 올라간다. 위쪽은 페이드 마스크다.
- 시계 레일: 두 창이 같은 테이프 초 눈금을 쓰므로 끝난 점의 위치 차이가 곧 1.8 배다.

첫 토큰 전에는 "prefill · …" 대기 상태를 1급으로 그린다. P 512 프롬프트라면 단독 쪽은 17.7 s 동안 빈 창이다. 첫 토큰이 오면 레일에 흰 눈금과 `first token X s` 가 박힌다. 끝나면 창 테두리가 한 번 밝아지고 `done X s · N tokens` 가 뜬다. 아래 가운데 라벨은 `▶ real time` 이었다가 배속 구간에서 `▶▶ 2× speed` 가 된다.

**HOW.** 위에서 아래로 놓인다.
- 40층 띠: y 236, 14 px 칸. 토큰은 ember 점이다.
- 라우터 격자: 32×12 = 384칸, 24 px 간격.
- 세 집: y 668–990.
  - 워크스테이션 유리(steel 테두리) 안에 RTX A6000 VRAM 과 RAM 이 있다.
  - 오른쪽에 DGX Spark(ember 테두리)가 있다.
  - 둘 사이는 132 px 의 점선 TCP 링크다.

H3 의 패킷 라벨은 집들 위 오른쪽 위 공간(y 590–622)에 두고, 안내선으로 링크를 가리킨다. H4 그래프의 x 는 RAM 너머 GB(눈금 0, 62, 94)이고 y 는 스텝당 ms(0, 10, 20)다. steel 띠(두 기울기) 위에 측정한 두 방의 점이 있고 ember 선은 ~7 ms 에 평평하다. H5 는 막대 둘이다. 단독 17.7 s 를 가득 채우고 Spark 는 그 1/3.6 이다.

**NUMBERS.** 위에서 아래로 놓인다.
- 제목 한 줄: 128 GB workstation 은 bone, + one DGX Spark 는 ember.
- 영웅 숫자 둘(decode 1.8×, prefill 3.6×)과 "each against the same workstation alone".
- 표 세 행: decode, prefill 값과 열마다 제 눈금의 가는 막대. 범위의 아래 끝까지는 진하게, 위 끝까지는 옅게 칠한다.
- 조건 세 줄: 모델·카드·링크 / P·depth·n·라운드·날짜 / RAM 캡과 CPU 그대로.

**END.** `bloomery` 132 px 650, ember 밑줄, 문구 두 줄. 마지막 프레임까지 머문다.

**자리표시 도장.** `placeholder` 가 참이면 −30° 로 `PLACEHOLDER TAPES` 두 줄을 그린다. 맨 마지막에 그려서 END 위에도 찍힌다.

## 검사

- `render.py audit`: 0.05 s 마다 그린 문자열을 모두 모은다.
  - UI 문자열의 숫자는 모두 `data.json` 값(테이프 원시 스탬프 제외)에 있어야 한다.
  - 창의 글자는 제 테이프 텍스트의 조각이어야 한다.
  - 한글은 Pretendard 로 그려져야 한다.
- `render.py probe`: 스펙의 여덟 시각. 이 라운드의 눈 판정은 이 시트로 했다.
- `render.py pops`: 한 프레임짜리 튐 0건.

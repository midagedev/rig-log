# #644 serve screen: the wordmark and furnace in half-block pixels over a placement panel and a serving panel (@juliankang4, MERGED)

bloomery-serve가 터미널에 그리는 시작 화면을 새로 디자인하고, 같은 그림으로 README 맨 위 이미지를 바꿉니다.

## What and why

`bloomery-serve` draws a start screen on a terminal once the server listens. This PR redraws it. The data it shows and the rules it reads them by are the same; only the layout and the art change.

The new screen, top to bottom:

- The bloomery wordmark and a bloomery furnace in half-block pixels. A `▀` cell carries two square pixels (its foreground and its background), so the letters and the furnace draw as solid shapes instead of broken glyph rows. The wordmark is warmed down its rows; the furnace has its flame, sparks, the bloom glowing in its arch and the tuyere at its side.
- A status line: a `READY` badge, the seat, and the load time on the right. The address sits under it.
- Two panels side by side. **placement** has a bar of where the plan put its routed experts (card, tier card, host) with a legend, then the card, tier, host and NVMe rows. **serving** has the placement and why, the architecture, a decide seat's model and head, the context and slots, and the prompt cache. A row neither panel names (the plan's card list, the `unread` row) runs the full width below them. A long value wraps first at the dots that separate its parts.
- The `try` curl lines and the two keys, `Ctrl+C` and `BLOOMERY_SCREEN=off`.

Colour: `COLORTERM=truecolor` (or `24bit`) draws the colours as they are; any other terminal gets the nearest colour of the 256-colour cube. `NO_COLOR` and `TERM=dumb` still draw it without colour, and a locale without UTF-8 still gets plain ASCII (`#`, `"` and `.` for the half blocks). Without colour the art keeps only its shapes: no shadow, no sparks, and the furnace's mouth and arch left open.

The second commit puts the same art at the head of the README: `docs/assets/banner.svg` and `banner-dark.svg` are `art()`'s pixels at eight units a pixel, with no background. The dark one keeps the screen's colours; the light one warms the wordmark down a darker ramp so its top rows show on a white page. They replace `logo.svg` and `logo-dark.svg`, which nothing else references.

Release notes: Changed: the start screen of `bloomery-serve` is redrawn: the wordmark and a furnace in half-block pixels, a status line, and placement and serving panels with a bar of where the experts went.

## Code shape

- [x] **No second copy.** The screen still reads every value through `facts()`; the panels only route its rows. The README banner is drawn from the same `art()`, so the two cannot drift.
- [x] **Model code holds only architecture facts.** Nothing model-specific changed.
- [x] **Dead code is gone.** The old box, its furnace and smoke rows and their helpers are removed, and so is the logo the banner replaces.
- [x] **No silent failure.** A record value that is no number is still named on the `unread` row. `bar_cells` returns `None` when no part holds experts or the counts overflow, and the bar is left off.
- [x] **Comments state what is true now.**
- [x] **No relaxed gate.** The four golden screens are rewritten by `SCREEN_BLESS=1`; the tests that read rows by the old `| label` box now read them by the label's column. New tests pin the half-block encoder, the bar's cell split, panel alignment beside wide characters, and the `COLORTERM` cases.
- [x] `cargo fmt` is clean, and `cargo clippy -p bloomery-serve -p bloomery-levers --all-targets` reports nothing in the two source files this PR changes.

Duplication found or removed (`path:line`): none.

`COLORTERM` is one more terminal variable the screen reads; it is on the `crates/serve/src/screen.rs` line of `tools/levers-direct.txt`, and the `BLOOMERY_SCREEN` row in `crates/levers/src/registry.rs` says what it does.

## What I ran into

This does not block the PR.

- The screen is 98 columns wide (the old box was about 80). On a narrower terminal the art's rows wrap.
- `api::tests::a_key_never_reaches_what_the_process_prints_or_serves` runs `target/debug/bloomery-serve`, so it fails in a fresh checkout until that binary is built. It pipes stderr, so the screen never draws in it.

## Hardware

An RTX 5090 machine (driver 595.99.02) for the build and the screenshot; a Linux CPU machine for the unit tests.

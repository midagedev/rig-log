# #777 metal: routed experts' grouped GEMM on a 64-row tile (prompt pass +16–19 % on M4 Pro) (@midagedev, MERGED)

The routed experts' grouped GEMM for the Metal prompt pass, on a 64-row tile. Part of #593.

The expert GEMMs took half of a 2048-row pass on the M4 Pro and ran well below the dense GEMM's rate. The cost was not the weight side: a probe that removed the weight staging moved the time by 5 %. It was the 32-row tile and a liveness test on every fragment inside the K loop.

- A tile is 64 weight rows by 64 activation rows. Each SIMD group takes 16 weight rows against every live 8-row activation fragment.
- The K loop is chosen once a tile from the run's fragment count, so nothing is tested inside it. Only live rows are staged.
- The sum order is the K loop's alone, so the outputs are bit-equal to the 32-row tile's. The new clause `grouped_oracle` holds this against the old tile, kept as an oracle in the gate.
- `metal_gemm_time --routed` times the grouped GEMM over a synthetic route table.

Geometry: threadgroup memory per tile grows from 7,680 to 10,240 bytes (f16 operands) and from 13,824 to 18,432 (f32); 128 threads as before. The timed A/B below is the evidence for the occupancy change.

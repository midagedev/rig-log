# #726 Mac port train 2: Metal kernels, the qwen35moe session, bloomery-serve-metal and KV checkpoints (#593) (@midagedev, MERGED)

Mac port train 2 (#593): the qwen35moe model runs on the Metal device end to end, behind `generate_metal` and a llama-server-compatible `bloomery-serve-metal`, and the server keeps a chat's prefix through checkpoints of the recurrent state.

What it adds:
- The Metal kernels for one qwen35moe token. Segmented and head-normed mat-vecs, the router, the expert gate-up pair and folded down, the gated delta step, decode attention (flash and merge), and the output head. Each is gated against an f64 oracle on the fixture's tensors, with a mutant per clause.
- The session runs a token on the device and one token ahead. A steady step allocates nothing on the host. It is a `runtime::Target`, with `generate_metal` and a profile step.
- `bloomery-serve-metal`. The vocabulary, chat surface and sampler factory move into the serve crate, so every backend shares them.
- Delta-state checkpoints over `runtime::seqstate`'s ledger. A checkpoint is each delta layer's live state lane plus its conv ring. The server splits prompt calls at message starts, so a later turn keeps everything up to its last message.
- Moves to common owners: the rope table goes to `chain`, the free/flip rule to `refset`, the qwen3moe plan loop to `chain`.

Train 1's review fixes are carried into the files this train rewrote (last commit).

# #779 metal: prompt call fixed costs (one buffer per layer, checkpoints copied once) (@midagedev, MERGED)

Fixed costs of a Metal prompt call. Part of #593.

A contributor's two-point fit showed about 100 ms of fixed cost per prompt call on the M3 and M5 Ultra, and chat turn 2 (a few short calls) took about 60 % of turn 1's time.

- A checkpoint copied 73.7 MB of delta state twice (pages → `Vec` → slot), and a cut copied it back twice. Each now copies once, straight between the shared pages and the slot: 24.7 → 1.3 ms a checkpoint.
- An unprofiled pass was one command buffer per op, about 200 a pass. It now commits one buffer per layer, each opened at the stream's token boundary and not waited, and settles the last one once. A layer bounds how long one buffer runs, so a long pass on a small chip stays clear of the GPU's command-buffer timeout. One buffer per pass measured the same within 1 ms. The profiled pass (`--pass-times`) keeps a buffer per op.
- `--pass-times` takes several sizes and prints `pass_wall` beside the summed op times. The server prints one line per prompt call (positions, ids, ms).

Gate `q_layers` (e2e): a 100-id pass commits one buffer per layer and waits once, and its pick, logits row, states, rings and cache rows equal the profiled pass's bit for bit. FAIL-first: one buffer per op (22), one buffer for the pass (1), and a layer buffer without the boundary wait (other picks) are each red.

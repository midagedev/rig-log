# #757 Metal: MLX 4-bit (affine) qwen35moe files decode on Apple Silicon (@midagedev, MERGED)

## What and why

Mac port (#593): the Metal backend reads MLX's affine 4-bit format, so a Qwen3.6 MLX checkpoint converted to a GGUF split (MLX_A4 weights, MLX_A8 router) opens and decodes on the Metal device.

- gguf gains the `MLX_A4` and `MLX_A8` block types: groups of 64 codes, then a BF16 scale and a BF16 bias (`w = s·q + b`). gguf owns their block bytes and value counts; every other reader takes them from its row.
- hf and model-hf read an MLX checkpoint folder into the qwen35moe map (`Family::Qwen36` beside `Qwen38`, with Qwen3.8's MTP draft kept). `tools/mlx-fixture.py` writes the qwen35moe fixture as an MLX folder for the gates.
- Metal: one decode owner per quant (`kernels/quant.metal`). The mat-vec, pair, fold and head bodies are generic over it, and `struct A4` joins Q4_K and Q6_K. A SIMD group owns four rows. `Kernels::with_geometry` refuses a row count the library's source does not define.
- chain: `SiteTy::MlxA4` sits outside the card kernel table (`BACKEND_SITES`). The qwen35moe reader takes a backend's site lists as data (`read::Sites35`). The card passes its lists as before, and the card's site code refuses `MlxA4` by name. Metal passes `session::SITES`, one `LAUNCHED` list held equal to the arena's quant set by a test.

# #766 gpu: run the routed NVFP4 gate, up and SwiGLU as one native launch (@juliankang4, MERGED)

Qwen3.8 NVFP4와 FP4-Local의 prompt 처리에서 routed expert의 gate, up, SwiGLU를 kernel 하나로 합쳐 중간 F32 쓰기와 읽기를 없애고 prefill을 빠르게 하는 작업입니다.

Part of #565.

## What and why

On a native FP4 build (the GB10 default, `sm_121a`) with both routed stacks in NVFP4 planes, a Qwen3.8 layer computes the card slots' gate GEMM, up GEMM and SwiGLU as three launches. The first two write their products to F32 scratch (`g` and `u`), and the SwiGLU reads them back and quantizes its result to Q8 for the down GEMM. At 4,096 tokens with top-10 routing that scratch is large.

This PR runs the three as one kernel, `gate_up_nvfp4_mma`, in `crates/gpu/src/gemm/nvfp4mma.rs`. Each block holds 64 rows of the gate stack and the same 64 rows of the up stack for one route tile in shared memory, issues the gate and up `mma` on the same activation fragment, applies SwiGLU in registers and quantizes each slot's two 32-value blocks from a shared tile. The F32 scratch round trip and one launch per layer go away. `quantize_nvfp4_32` then packs the down GEMM's FP4 from that Q8, as it already does for other callers.

- `Gemm32Kernels::enqueue_gate_up_sel32` and `GateUp32Args` (`crates/gpu/src/gemm/gemm32.rs`) are the one entry, and `wide38.rs` is its caller. It takes the fused path only on a native FP4 build with both stacks in NVFP4 planes and the activations in the native form. Every other build and stack runs the existing gate GEMM and `enqueue_up_swiglu32`, the launches main runs today.
- The native host launcher takes one argument struct, `GateUpArgs`, plus the stream, the activations and the fault sink, so it needs no lint allowance. Kernel entries keep the function-level `too_many_arguments` allowance the kernel-entry rule gives them.
- The epilogue calls `crate::elem::silu_mul`, the function the activation path runs for SwiGLU, so the arithmetic has one owner. The kernel takes no activation-rule parameters.
- After the launch the native path marks the activations filled through `GemmAct32::fill`, like every other quantizer launch, so the BF16 form is forgotten as well.
- The K staging walk of `gemm_nvfp4_mma` and `gate_up_nvfp4_mma` is one macro, `nvfp4_walk!`, so the protocol has no second copy.
- The 32-value Q8 rule keeps one owner: the per-lane core of `quant32_group` is split out as `quant32_lane`, and both the old quantizer and the new epilogue call it.
- The launch inputs are checked once at the entry. The entry also refuses down activations whose K differs from the gate and up rows, by name.
- Host experts, the down GEMM and the top-k sum order are unchanged.
- `tools/ref/ptx-shapes/sm_121a-cc12.1.tsv` gains a pinned row for the new kernel (spill 0, JIT local 0). `tools/unsafe-ratchet.txt` carries a `PIN` line for the new kernel's `unsafe` blocks (2297 to 2312). The module-wide `too_many_arguments` allowance in `nvfp4mma.rs` is gone; the remaining function-level allowances carry the kernel-entry reason, and the two exemptions that need a dated pin (the `swiglu` device-core scope and the `nvfp4_pack_q8` range loop) have one.

Release notes: Changed: Qwen3.8 NVFP4 and FP4-Local prompt prefill is about 3% faster on a DGX Spark.

## Code shape

- [x] **No second copy.** The K walk is `nvfp4_walk!`, the Q8 rule is `quant32_lane` and the SwiGLU arithmetic is `elem::silu_mul`, each shared by all of its users.
- [x] **Model code holds only architecture facts.** The common owner gained no per-model branch, flag or trait method.
- [x] **Dead code is gone.** The check that the rows are a multiple of 64 is dropped because the native activations already guarantee it, and the kernel and launcher carry no unused parameters.
- [x] **No silent failure.** A non-finite gate or up value stores the block as refused and raises `QuantColumn`, a refused expert id raises `ExpertId`, and a down K that differs from the gate and up rows is refused by name. The gate's reset and replay faults are asserted, not dropped.
- [x] **Comments state what is true now.**
- [x] **No relaxed gate.** No band, tolerance or lint moved. The PTX shape table and the unsafe ratchet carry the new kernel's row and a `PIN` line, and the gate that covers the fused launch now replays over reset buffers (see "What I ran").
- [x] `cargo fmt` is clean (`tools/mac-check.sh fmt`, rc 0). Clippy at `sm_121a` reports no warning in code this PR adds (see "What I ran into"); the default-target lint count is checked by CI.

Duplication found or removed (`path:line`), or "none": none left on the head. The duplicate scan matched the new kernel against `gemm_nvfp4_mma` (the K walk, now the shared macro; the fragment step and the epilogue differ) and against `swiglu_nvfp4_32` (it reads F32 `g` and `u` from global memory and packs FP4, while the new kernel computes both in registers and stores Q8). Both reuse `elem::silu_mul` and the shared Q8 owner.

## What I ran

All gates and timings ran on a DGX Spark. The first timed sitting ran on the commit before the kernel's argument cleanup; the second, shorter sitting ran on this head. "What I ran into" lists what that changes.

### Output is unchanged

`nvfp4_gate_up` compares the fused launch with the existing split launches on the same route at four shapes (64x64 over 9 tokens, 128x128 over 50 with a refused expert id, 192x256 over 37 with a NaN in token 5, 640x2560 over 131), three card experts, one host place and top-2, and checks the down-K refusal. It checks every card slot's Q8 bytes, the down GEMM's output bits and the expected fault on eager and graph replay. After capture it resets the output to its sentinel and the down activations to the quantization of a zero input, replays the graph, and then reads the Q8 bytes and asserts that the replay's fault equals the eager fault. The fused path leaves `g` and `u` at their sentinel.

## What I ran into

None of this blocks the PR.

- The first timed sitting ran on the commit before the kernel's argument cleanup. That cleanup removed two unused arguments from `gate_up_nvfp4_mma` and changed no arithmetic, so that kernel's PTX digest moved (`08cd504b`) while its registers, shared memory and spill read the same, and every other entry's resource columns are equal. I did not repeat the three-round sitting; the short sitting above ran on this head and matches it. The full `ptx-compare` of this head against the timed commit did not run: the node's repository had no object for the commit it compares with, so the step stopped. Every gate and the spill check had already passed.
- Clippy at `sm_121a` (`CUDA_OXIDE_TARGET=sm_121a ./tools/mac-check.sh lint`) reports seven warnings, the same seven as main: the `swiglu` and `product` host launchers in `nvfp4mma.rs`, each counted for the lib and the lib test, and `gpu-gates/src/bin/shared/q38_combine.rs:111`. None is in code this PR adds.
- The change is measured on one DGX Spark only. No RTX 5090 run and no TP=2 run was done, and the non-native and non-NVFP4 paths keep main's launches without a timing of their own.
- The fused kernel covers gate, up and SwiGLU, not the down GEMM. It still writes Q8 and packs the down's FP4 with `quantize_nvfp4_32`, which is a second launch per layer after the fused kernel. Packing the FP4 inside the epilogue needs each column's global scale, which depends on every row tile of the column, so it would need a cross-block reduction or a per-tile scale format. The top-k sum is main's.
- The profiled kernel table is one window per side, so its kernel times are a single observation.

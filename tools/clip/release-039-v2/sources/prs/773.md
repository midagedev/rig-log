# #773 metal: batched prompt prefill for Qwen3.6-35B-A3B (@midagedev, MERGED)

Batched prompt prefill for the Metal engine (Qwen3.6-35B-A3B). Part of #593.

A prompt longer than 8 ids now runs as batched passes, one per ubatch (the CUDA engine's rule), instead of one decode step per id.

- Row kernels: delta net over rows (prep split off the recurrence), attention norm/rope over rows, `norm_rows`.
- Quantized GEMM for A4 (MLX 4-bit), Q4_K and Q6_K, with f16 and f32 operands.
- MoE over rows: router selection, route table, grouped expert GEMMs, combine in the decode's order.
- `attn_prefill_f16`: a flash attention over a tile of query rows against the f16 cache.
- `Session::pass`; `Target::prompt` cuts the prompt with `call_batches`. Prompts of 8 ids or less keep the step path.
- One Metal residency set per stream. Without it the driver wired the weights at the first prompt (about 2.3 s) and let early layers lapse during a long pass, so the first decode step after it took up to 1.6 s.

Gates (M1 Pro, fixture): `just lab-metal` (every kernel mutant red on its clause), `just lab-metal-e2e` (prompt ≤ 8 ids bit-equal to steps, state band, chunk-size invariance, reference distance, free run, `r_resident`), `mac-metal-lint`, `check-unsafe`, `check-comments`, `check-recipes`.

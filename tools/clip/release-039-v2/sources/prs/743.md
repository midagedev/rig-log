# #743 serve screen: reflow the start screen at the terminal width (@juliankang4, MERGED)

서버 시작 화면이 98열보다 좁은 터미널에서 줄이 넘쳐 깨지던 문제를, 실제 터미널 폭을 읽어 세로 배치로 그리도록 고칩니다.

Part of #565. Tracked in #699.

## What and why

The start screen is laid out for 98 columns: a logo, two side-by-side panels and a curl example. In a terminal narrower than that, every wider line wraps in the terminal itself, so the panels fall out of alignment and the curl command breaks across lines at arbitrary places. The screen came in with #644 and has never looked at the terminal's width. It affects anyone who starts `bloomery serve` in an 80-column terminal or a narrow split.

This change reads the real column count from stderr each time the screen is drawn, so a resize while the server loads is picked up. At 98 columns and above the layout and its golden files are unchanged. Below that:

- the logo is drawn as text, and the placement and serving panels stack in one column;
- a label and its value wrap separately when the screen is narrower than the fixed label width;
- ANSI color codes do not count toward the width, and Korean and combining characters are measured with the existing `char_width`;
- a long curl URL is split with quoting and line continuations that keep it one shell argument, and IPv6 addresses are quoted in brackets;
- a width below four columns is refused with a named diagnostic and nothing is drawn, since a quoted shell chunk needs a character, two quotes and a continuation. A non-TTY stderr or a disabled screen still never arms, as before.

Every record fact, address, example and the stop hint stays on screen at every width. The width lookup is a `TIOCGWINSZ` call in `crates/serve/src/screen.rs`, and `tools/unsafe-ratchet.txt` moves `serve` from 6 to 11 unsafe blocks for it and for the PTY test. Each new block has its SAFETY invariant. The diff also carries three earlier commits that move the tier count selection for the details and the bar into one owner, so the narrow layout reuses it instead of copying it.

Release notes: Fixed: the start screen now fits terminals narrower than 98 columns instead of wrapping its layout.

## What I ran

All runs are CPU only, on a Linux machine, with no model and no GPU. The command is the same for each arm below, with the tests named in each line.

FAIL-first: on the old renderer, with only the PTY test added, a real 80-column PTY receives a 98-column line.

```text

test result: FAILED. 0 passed; 1 failed; 0 ignored; 0 measured; 345 filtered out; finished in 0.05s

```

On the commit before the last one, whose renderer split shell words at the column edge, the 40-column case of `narrow_screens_keep_every_record_value` fails because a curl argument gains a newline: `left: ["-H", "Content-Type: application/json\n", "-d"]` against `right: ["-H", "Content-Type: application/json", "-d"]`.

I also broke the fix in three places to check that each guard catches its mutant, and each run failed as expected (rc 101):

- the four-column refusal lowered to three columns: `terminal_viewport` fails;
- the viewport comparison `columns.min(ART_W)` changed to `columns.max(ART_W)`: `narrow_screens_keep_every_record_value` fails on the 80-column curl line;
- the branch that joins a long curl URL removed: the same test fails because the URL then contains a real newline and the shell output goes from five lines to six.

After restoring the source and checking `git diff` was clean:

```text
timeout 900 cargo test -p bloomery-serve --lib screen:: -- --nocapture
test result: ok. 17 passed; 0 failed; 0 ignored; 0 measured; 333 filtered out; finished in 0.57s
rc 0
```

The 17 tests include the existing golden, tier-fact, several-card, Korean-alignment and half-block tests, unchanged. The new ones run a real PTY at 4, 80, 97, 98, 99 and 120 columns, resizes between 98 and 80 and between 98 and 4 in both directions, and the 0 to 3 column diagnostics. A renderer matrix at 4, 9, 12, 20, 40, 80 and 97 columns, in UTF-8 without color, 256 colors and truecolor, checks the display width and that every record value is present. IPv4, longest IPv6, IPv6 with a scope ID and long-address curl examples are fed to `sh` and the arguments are compared with the originals. The curl function only prints its arguments; no request is sent. A pipe on stderr draws nothing and `arm(false)` stays off.

The layout reads the terminal width at each draw, plus the color and locale variables. `terminal_viewport` sets the width, `TERM` and the color choice on a real PTY, so a later report that gives the terminal width (`stty size`), `TERM` and the start record can be replayed in that test without a separate probe.

## 프롬프트 경로의 병목, 오늘의 main 에서 다시 읽음

Spark 노드가 프롬프트 블록을 받는 설계(r4prompt)는 9월 29일의 S0 측정(plan a, prose P512: 호스트 union 45.72 ms, card_in 11.53 ms 한 층-배치)을 근거로 "프롬프트는 호스트 union 이 묶는다, 노드가 그 시간을 덜어 pp512 +5…+8 %"를 유도했다. 그 근거가 오늘도 참인지, 그리고 P4096 행의 분모(S0 의 union 44.19 × 320 이 체인 10.88 s 보다 커서 맞지 않던 것)가 무엇인지를 한 임대로 읽었다: A6000, main f83a69dea, `BLOOMERY_STEP_STATS=1 just depth-gpu-ds41 prose:512 prose:4096`, 카드 `docs/cards/sparkr4-union.card`(예측 43.4..48.0).

틀렸던 것: 두 달 된 앵커를 모델 입력으로 쓴 것. 프롬프트 경로는 그 사이 두 번 바뀌었다. 다음은 r4prompt 1.5 를 이 행으로 다시 세우고, A/B 카드 B 는 P4096 만 연다.

## Spark 를 V4.1 의 expert tier 노드로 — 첫 bind 가 가르쳐 준 세 가지 (sparkr3)

TCP 와이어와 count word 가 main 에 오른 뒤(bloomery 1ace3447c) Spark 의 tier_server(r3node 트리, sm_121a 네이티브 빌드,
`--features deepseek41`)에 워크스테이션의 stage 를 `--place bp` 로 붙였다(`BLOOMERY_TIER_NODES`, `BLOOMERY_TIER_LINK=tcp`,
`BLOOMERY_PREFILL=steps`). 재지 못한 것: a. 대신 세 가지가 나왔다.

1. **플랜은 Spark 의 census 를 카드 스펙으로 받아 tier 를 125.8 GB(7,499 experts)로 잡는다.** 통합 메모리 121 GiB 의 거의 전부다.
   첫 open 은 모델 복사 직후 page cache 가 찬 상태라 커널 OOM(NVRM NV_ERR_NO_MEMORY)으로 죽었고, cache 를 비운 두 번째는
   791 MB 를 남기고 올라왔다. Spark 는 공유 기계라(docker 컨테이너가 20–45 GB 를 쓴다) 노드의 room 은 total 이 아니라
   free 에서 파일 읽기 페이지와 다른 세입자를 뺀 값이어야 한다. `BLOOMERY_CARD_BUDGET` 은 노드가 있으면 한 값만 받아 A6000 의
   몫까지 깎는다 — 노드별 표기가 필요하다(placement, ~20줄).
2. **프롬프트 배치는 노드 tier 를 거부한다**(`feed the prompt as steps`). 지금 코드로 Spark 는 디코드에만 기여한다.
3. **Spark 의 드라이버 580.178.04 는 CU_STREAM_MEM_OP_ATOMIC_REDUCTION 을 "invalid argument" 로 거부한다.** 첫 스텝의
   tier go(`[wait_geq, add u32::MAX]`)가 노드 스트림에서 죽었다. 드라이버 API 탐침(CUDA 13.3 cuda.h 로 양쪽에서 빌드):

   | 메모리 | wait32 | write32 | batch(wait, write) | batch(atomic add) |
   |---|---|---|---|---|
   | GB10 580.178.04: cuMemHostAlloc(DEVICEMAP) | ok | ok | ok | invalid argument |
   | GB10: cuMemHostRegister(DEVICEMAP) | ok | ok | ok | invalid argument |
   | GB10: cuMemAlloc | ok | ok | ok | invalid argument |
   | GB10: managed | invalid argument | – | – | – |
   | A6000 615.71.09: 위 셋 | ok | ok | ok | ok |
   | A6000: managed | invalid argument | – | – | – |

   apt 에 더 새 드라이버는 없다. 펌프는 세대(generation)로 done 을 읽으니 상수 write 로 대신할 수 없다. 엔진 쪽 수정은
   add 를 system-scope atomic 커널 한 런치로 대신하고(층당 go 하나·done 하나, ≈ 2·c_node), 어느 쪽을 쓸지는 버전이 아니라
   컨텍스트 open 때의 탐침으로 정한다 — 라운드 r3b.

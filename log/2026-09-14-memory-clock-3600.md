# 메모리 클럭: 3200→3600, 벽은 어디인가

**2026-09-14 밤.** 낮 대역폭 작업이 읽기 상한 131 GB/s에 BIOS 메모리 클럭 ~10%를 남기고 끝났다. 그 단계다. DIMM을 DDR4-3200→3400→3600→3666→위 세 번 실패로 걸었다. 매 정거장 같은 프로브·스트레스·identity·디코드. BIOS 작업은 사용자, 측정은 기계.

전부 같은 램이다. 삼성 M378A4G43AB2-CWE 32 GB 2Rx8 non-ECC UDIMM 8개, 채널당 하나, defaults 리셋 후 BIOS 1901. 보드 ASUS Pro WS WRX80E-SAGE SE WIFI, CPU 5975WX(4 CCD).

## 매 클럭 chain

`llm.service` healthy 보고 뒤, 다른 것 없는 기계에 클럭당 스크립트 하나:

1. 대역폭: 코어 0–31 고정 `bw 32 8 5`(읽기 8 GiB, 5회 best), CCD0 8스레드·2 CCD 16스레드 각 3회
2. 탐욕 identity A: 고정 프롬프트 20개, temperature 0, 64토큰, 서빙 포트 상대
3. `stress-ng --cpu 32 ... --vm 8 --vm-bytes 16G ... --verify --timeout 600` — RAM 128 GB에 패턴 라이터 여덟, 쓴 것 되읽기, 10분(3400만 5분)
4. 탐욕 identity B, A와 바이트 대조
5. 서빙 포트 400토큰 싱글스트림 디코드 3회
6. 전후 커널 로그 MCE/EDAC·PCIe AER 카운터

`--verify`가 요점이다. 이 DIMM은 ECC 없어서 한계 클럭이 에러 카운터를 안 올린다. 틀린 바이트를 돌려주고 입을 다문다. 자기 되읽기 스트레스가 아니면 안 보인다.

대역폭 GB/s, 3실행 best-of-5의 best. 3200행은 아침 측정(버퍼 16 GiB). 나머지는 8 GiB라 같은 클럭에 ~1% 높게 나온다. 한 클럭 실행간 흩어짐 ~2%(3600 두 행)라 3600 두 대역폭 수치는 같은 숫자다.

마지막 행이 현재 구성이다.

## 숫자의 말

**3600까지 클럭이 대역폭을 1:1로 움직였다.** 3200→3600 클럭 +12.5%, 32스레드 읽기 +12.6%(131.2→147.7). CCD당 수치도 같이(40.2→44.3)라서, 아침의 4 CCD 상한은 패브릭 상한이 아니라 메모리 클럭 따라가는 메모리측 상한이다.

**3666은 3600보다 나빴고, 이어서 틀렸다.** MEMCLK 1833에서 32스레드 143으로 떨어지고 싱글 CCD는 44.3 유지 — 패브릭이 메모리 클럭 1:1을 놓친 모양이다. 이 보드 Infinity Fabric 클럭은 1800 MHz까지 메모리 클럭을 자동 추종, 손으로 못 박는다(아래). 그래서 3666은 패브릭 앞선 메모리다. 이어서 10분 스트레스가 돌려줬다.

```
stress-ng: fail:  [6142] lfsr32: detected 46 memory errors
... (8 워커 중 6 실패, LFSR·random 패턴에 집중)
stress-ng: info:  [6099] failed: 6: vm (6)
```

10분에 오독 139회, 비트 전이 많은 패턴에 몰리고 단순 패턴 0 — 불량 셀이 아니라 타이밍 마진 모양이다. 커널 MCE·EDAC 카운터는 내내 0. 조용히 깨지는 non-ECC, 오후에 예측한 그대로다. `--verify` 없었으면 "3600보다 3% 느리지만 fine"으로 보였을 클럭이다.

**3600이 끝이라 마진을 준다.** Auto 1.2 V에 통과했지만 다음 단이 1.3 V에 깨지니, 8 듀얼랭크 DIMM의 이 IMC 경계에 3600이 있다. 상용 구성 DRAM 전압 1.30 V — JEDEC/XMP 범위 안(1.2 nominal, XMP 킷 전부 1.35), 베어 UDIMM에 잴 열비용 없음, BMC 되읽음 채널군별 1.29/1.28 V.

**디코드는 대역폭보다 덜 움직였다.** 3400→3600 대역폭 +6%에 싱글스트림 디코드 +2% 남짓(26.0→26.3, 실행간 밴드 안). 서빙 프로파일 디코드 예산에 메모리 클럭이 안 닿는 GPU 몫·draft 몫이 있다. 3200 클린 디코드행은 오늘 못 땄다(이른 수치들은 다른 프롬프트·3스트림). 3200→3600 디코드 전량은 여기서 주장 안 한다. 3200으로 리부트 한 번 + 같은 3실행이 필요하다.

## 펌웨어의 유무

매뉴얼(E18120)이 셋 다 침묵해서 만져서 확정했다.

- **Infinity Fabric 클럭 항목 없음.** 컨슈머 보드의 "Infinity Fabric Frequency and Dividers" 메뉴가 워크스테이션 펌웨어에 없다. 매뉴얼에 "FCLK"·"Infinity"·"UCLK" 없음. AMD CBS → DF Common Options에는 scrubber·NUMA·interleave뿐이다. 패브릭은 1800 MHz까지 메모리 클럭 1:1 자동 추종, 추종 여부의 유일한 되읽음은 대역폭 프로브다(리눅스에 sysfs 없음).
- **Auto DRAM 전압은 메모리 클럭 무관 1.2 V, 부하에도 안 움직인다.** AMD CBS에서 메모리 클럭을 박아도 Ai Tweaker는 전부 Auto로 읽히고, Auto는 SPD 기본값이었다. 3400·3600에 BMC 1.22 V, idle·메모리 스트레스 동일(같은 샘플에 VCORE 0.74→1.10 V). 매뉴얼 Ai Tweaker → DRAM ABCD/EFGH Voltage(p.18, 0.500–2.000 V)는 먹는다. 1.30 입력이 1.29/1.28 V로 되읽혔다.
- **Memory Clock Speed는 목록이다.** AMD CBS → UMC Common Options → DDR4 Common Options → DRAM Timing Configuration → Accept → Overclock Enabled → Memory Clock Speed, MEMCLK 값(DDR 수치의 절반): 1700=3400, 1800=3600, 1833=3666, 1867=3733, 1900=3800.

## 키보드 없이 BIOS 들어가기

둘 다 오늘 먹혔다. 하나면 된다.

```
sudo systemctl reboot --firmware-setup      # UEFI OsIndications 비트
sudo ipmitool chassis bootdev bios          # BMC 일회성 오버라이드, 다음 부팅만
```

두 번째는 OS가 안 떠도 호스트 밖에서 된다(`ipmitool -I lanplus -H <bmc> -U <user> chassis bootdev bios` 후 `chassis power cycle`).

## POST 안 되는 클럭에서 복구

3800이 트레이닝 실패. 보드가 재시도하고, 준 시간 안에 스스로 안전 클럭에 안 떨어져서, 물리 CLR CMOS 버튼을 썼다. BMC 웹 UI에 원격 CMOS 클리어·BIOS 기본값 액션 없음 — Maintenance 메뉴는 BMC 펌웨어·설정뿐이다. 이 복구는 케이스에 손이 가야 한다. 이 보드 CMOS 클리어는 전부 리셋하고, 뒤에 다시 넣을 목록은 [`docs/wrx80e-bios-setup.md`](../docs/wrx80e-bios-setup.md#after-a-cmos-clear)에 있다.

## 지나가며 둘

PCIe AER 카운터가 3600 실행 중 A6000 루트 포트(`00:03.1`)에 corrected Data Link Layer 에러 2건을 기록했다. 오후 삼성 NVMe의 같은 부류 뒤다. 루트 포트 다른 장치 둘, 둘 다 corrected, 둘 다 메모리 스트레스 중 — WKS-21에 볼 패턴으로 filed, 메모리 클럭 소행 아님.

공랭이 풀부스트 10분 스트레스 내내 패키지를 62–69 °C에 잡았다(약 285 W 패키지, 팬 고정 2200 rpm).

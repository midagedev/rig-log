# 넘을 선은 기본값이 아니었다 — 84.86 tok/s, ik 기본 82.78·최속 84.19

2026-09-21 아침(측정 시각은 9월 20일 19–21시대 UTC), [-a](2026-09-21-a-the-skew-that-was-the-timer.md)의 79.74 tok/s에서 이어진다. 같은 대상(DeepSeek-V2-Lite-Chat Q3_K_M, CPU 전용, 32스레드), 같은 규약: 속도 판정은 `just ab-decode`의 같은 임대 네 바퀴 상대값이다.

## 먼저 상대를 다시 쟀다

지금까지 "ik"는 `llama-bench -ngl 0 -t 32 -p 0 -n 96 -r 2`, 즉 기본 플래그였다. "ik를 넘는다"가 목표가 된 시점에 그 선이 ik의 천장인지부터 물었어야 했다. 같은 임대에서 다섯 조합:

| ik 플래그 | tg96 tok/s |
|---|---|
| (기본) | 82.66 ± 0.39 |
| `-fmoe 1` | 82.22 ± 0.43 |
| `-rtr 1` | 83.77 ± 0.09 |
| `-fmoe 1 -rtr 1` | 84.03 ± 0.15 |
| `-mla 3 -fa 1 -fmoe 1 -rtr 1` | **84.55 ± 0.01** |

넘을 선은 82.7이 아니라 84.5 근처다. 러너(`tools/ref/decode-measure.sh`)는 이제 ik를 두 번 잰다 — 기본값과 이 조합 — 그리고 "넘었다"는 말은 둘째 행을 상대로만 한다.

## 비용 두 배 프로브

perf 비율을 비용으로 읽다가 세 번 틀렸고(-k, -a), 이번에도 perf는 `quantize_col`이 메인 스레드 표본의 14%라고 했다. 그래서 다른 방법을 썼다: 의심 가는 직렬 일을 **일부러 두 번 돌리는** 빌드를 만들어 HEAD와 같은 임대에서 대조한다. 느려진 만큼이 그 일의 스텝 비용이다(둘째 실행은 캐시가 따뜻하니 하한에 가깝다).

| 프로브 | tok/s (네 바퀴 평균) | 읽기 |
|---|---|---|
| HEAD | 80.05 | |
| 메인 스레드의 인라인 활성값 양자화를 2회 | 79.03 (−1.3%) | 스텝당 ~0.16 ms |
| swiglu를 2회 | 79.35 (−0.9%) | 스텝당 ~0.11 ms |
| 층마다 빈 디스패치 둘 추가(별도 임대, HEAD 80.15) | 79.37 (−1.0%) | 제자리 디스패치 하나 ≈ 2.3 µs |

perf의 14%는 프로브로 1.3%였다. 풀 벤치의 빈 디스패치 1.61 µs는 스텝 안에서 2.3 µs다. 워크트리 하나, 한 줄 패치, A/B 한 번 — 구현 라운드를 쓰기 전에 그 라운드의 상한을 잴 수 있다.

## 넣은 것

| 변경 | 같은 임대 A/B (tok/s, 네 바퀴 평균) | |
|---|---|---|
| 헤드 체인을 디스패치 하나로: q_nope2 → flash → wv_b를 (토큰, 헤드) 행마다 한 워커가 (`attn::attn_heads_fused`) — GLM-5.3 위임 | 80.36 → 83.65, 프리필 126.1 → 132.6 | **+4.1%**, 4/4 |
| 라우터의 F32 내적을 ik의 레인 순서로 (`qdot::dot_f32`) | 83.41 → 84.06 | +0.8%, 4/4 |
| rms_norm을 ik의 융합 norm 순서로 (`qdot::sum_sq_f64`) | 83.81 → 84.07 | 잡음 안(3/4; 사전 증인에 journalctl 112%) |

**헤드 체인.** 레벨1 프로파일에서 `q_nope2_absorbed` 37.35 + `flash_attn_latent` 28.52 + wv_b의 `matmul_q_batch` 49.63 + `wv_b_heads` 자기 시간 18.11 = 96스텝에 133.6 ms, 스텝당 1.39 ms(10.6%)였다. 층마다 디스패치 넷(wv_b의 입력 16열은 인라인 임계 8을 넘어 양자화도 풀로 갔다)과 메인 스레드의 헤드별 게더·스캐터가 들어 있었다. 세 단계는 (토큰, 헤드)마다 독립이고 flash는 이미 헤드 하나를 워커 하나가 돌고 있었으니, 한 워커가 자기 헤드의 q 슬라이스를 양자화하고, 열 전체의 `q_nope2_cells`를 돌고, flash 행을 돌고, 그 출력 열을 양자화해 v_up 128행을 내적하는 디스패치 하나로 접어도 모든 호출이 받는 바이트가 같다. 새 게이트 `hw_attn_heads_fused_bit_identical`이 기존 세 함수의 사슬과 세 출력을 `to_bits`로 대조하고(FAIL-first: (c)의 입력 열을 하나 밀면 rc 101), 옛 함수 셋은 오라클로 남았다. 뒤의 프로파일에서 `attn_heads`는 호출당 26 µs(스텝당 0.70 ms), 스텝당 디스패치 243 → 162, 할당 765 → 630(LIMIT 700). 위임은 effort max, 워크트리 격리, 리드가 diff를 읽고 게이트 10종 + POISON 4종 + `BLOOMERY_STEAL=0`을 다시 돌렸다(전부 rc 0).

**라우터와 norm: 빨라지면서 정확해졌다.** 둘 다 "SIMD로 바꾸면 합 순서가 달라져 게이트가 열린다"고 미뤄 둔 자리였다. 거꾸로였다. ik의 F32×F32 커널(`iqk_gemm_floats.cpp`의 `mul_mat_Qx_Qy_MxN`)은 8레인 누산기 하나에 첫 블록은 곱, 이후는 `fmadd`, 마지막에 `hsum_float_8`이다. 우리의 스칼라 좌→우 합이 오라클에서 3.8e-6 떨어져 있던 이유가 그것이고, 같은 순서로 돌리니 라우터 로짓의 max|diff|가 **0**이 됐다. rms_norm도 같다: ik의 융합 norm은 f32 제곱을 **f64로** 누산하고 `(scale·gain)·x` 순서로 곱한다. 우리는 f32로 누산하고 `(x·scale)·gain`이었고 오라클과 3.4e-5 떨어져 있었다. 맞추니 `attn_norm-0`, `result_norm`, `result_output`이 전부 max|diff| 0이다. 두 게이트를 1e-4에서 0으로 조였고, 옛 소스는 그 줄에서 실패한다(각각 `max |diff| = 3.8146973e-6`, `3.4332275e-5`, rc 101). f64 누산은 AVX2에서 8레인으로 돈다 — 좌→우 합과 f64 반올림만큼 다르고 f32로 좁히면 같다(정확한 반올림 동률은 예외; 도출이고, 단위 테스트는 네 길이에서만 확인한다). 속도는 라우터 +0.8%, norm은 잡음 안이다.

## 헤드라인

같은 임대, 단발 96스텝 대 `llama-bench -r 2`:

| | tok/s |
|---|---|
| bloomery N=96 | **84.86** (11.8 ms/토큰), 프리필 129.35 |
| ik 기본 플래그 tg96 | 82.78 ± 0.04 |
| ik `-mla 3 -fa 1 -fmoe 1 -rtr 1` tg96 | 84.19 ± 0.51 |

증인: 세 구간 모두 `busiest`는 nvidia-smi 3.4% 아래(한 줄에 `ps 200%` — 증인 자신의 `ps`다), loadavg 4.4–4.6은 직전 빌드의 꼬리다. ik 기본값은 넘었다(+2.5%). 최속 조합과는 **같은 선**이다: 이 임대의 84.19 ± 0.51은 넘지만 앞 절의 84.55 ± 0.01과는 0.4% 차이고, 우리 쪽은 단발 측정이라 오차 막대가 없다. "넘었다"고 쓰려면 이 행이 몇 번 더 같은 방향이어야 한다. 어제 아침 2.10배, 저녁 1.35배, 새벽 1.044배였다.

## 남은 것

프로브가 말하는 상한: 활성값 양자화와 swiglu를 디스패치 안으로 옮기면 합쳐서 ~2.2%. 헤드 디스패치는 16개 작업이라 워커 16이 논다 — wv_b의 128행을 짝 워커에 나눠 주면 호출당 26 → ~19 µs, 스텝당 ~0.19 ms(도출). ik의 `-rtr`(행 인터리브 재배치)이 ik에게 주는 1.3%는 우리에게도 열려 있는 로드 시점 변환이다.

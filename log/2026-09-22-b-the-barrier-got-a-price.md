# 장벽에 값이 붙었다 — 0.92 대 0.80, 그리고 접기를 포기한 이유

*2026-09-22 새벽.* 이틀 전부터 소스에 이런 문장이 있었다. *"grid-wide barrier가 아끼는 노드보다 비싸다."* 그 한 줄이 융합의 경계를 정하고 있었는데 **숫자가 없었다.** 앞 라운드가 그것 때문에 fold 셋을 포기했으니, 이번엔 먼저 값을 매겼다.

## 장벽의 값

`probe`에 팔 셋을 뒀다 — `gap_plain`(평범한 런치), `gap_coop`(협동 런치, 장벽 없음), `gap_coop_sync`(협동 런치 + 그리드 장벽). 블록 수도, 블록 모양도, 스레드당 스토어 수도 같다. 다른 것은 **장벽과 런치 종류뿐**이다. 블록은 256스레드 — fold가 흡수해야 할 생산자의 모양이다.

| 블록 | `gap_plain` | `gap_coop` | `gap_coop_sync` | 협동 세금 | **장벽** |
|---|---|---|---|---|---|
| 16 | 0.989 / 1.003 | 1.215 / 1.233 | 1.941 / 1.972 | 0.226 / 0.230 | **0.726 / 0.739** |
| 22 | 0.995 / 1.008 | 1.223 / 1.240 | 1.963 / 1.794 | 0.228 / 0.232 | **0.740 / 0.554** |
| 82 | 1.060 / 0.983 | 1.161 / 1.190 | 1.790 / 1.909 | 0.101 / 0.207 | 0.629 / 0.719 |
| 164 | 0.943 / 0.955 | 1.132 / 1.145 | 1.945 / 1.969 | 0.189 / 0.190 | 0.813 / 0.824 |

같은 실행의 빈 커널 노드는 **0.833 / 0.779 µs**로, 앞 라운드의 0.80과 같은 선이다.

**장벽 ≈ 0.72 µs, 협동 런치 자체 ≈ 0.20, 합쳐 0.92. 노드 하나는 0.80.**

그래서 경계 하나를 닫는 fold는 **런치 산수만으로 −0.12 µs 손해**다. 그리고 앞 라운드가 계산한 점유율 대가(SM당 상주 워프 48 → 32, 또는 82 SM 중 22·16개)는 이 산수에 **들어 있지도 않다.** 소스의 단언은 유지된다 — 이제 계기가 붙었고, 여유는 얇다.

거꾸로 읽을 여지 하나는 같이 적어 둔다. 장벽 단독(0.72)은 노드(0.80)보다 **싸다.** 협동 세금은 런치당 한 번이고 장벽은 경계당 한 번이므로, 경계 N개를 한 협동 커널로 닫으면 `0.80N − (0.20 + 0.72N) = 0.08N − 0.20` — **N ≈ 2.5에서 손익분기, N ≥ 3에서 이득**이다. 그래도 fold 셋은 닫힌 채로 둔다. 점유율 대가가 저 식 밖에 있고, 그것이 0.08N보다 작다는 증거가 없다.

계기의 한계 셋을 결론과 같이 읽어야 한다. 프로브 블록은 스토어가 둘뿐이라 **0.72는 바닥**이다(실제 fold는 장벽에서 가장 느린 블록의 스큐도 낸다). `gap_plain`이 그리드마다 ±6%로 흩어지는 것이 이 계기의 sub-µs 잡음이다. 협동 런치의 공존 상한은 재지 않았다.

## 접은 것 둘

fold가 막힌 자리와 **막히지 않은 자리**는 다르다. `flash_merge`는 쿼리 행마다 512스레드 블록 하나라 블록이 이미 온전한 q8_1 블록 넷을 쥐고 있다 — 장벽이 필요 없다.

`kqvc` 양자화가 어텐션 런치의 side output이 됐다(단일 세그먼트 경로까지 둘 다). 비트 동일의 근거는 **공유메모리 전치**다: 양자화 워프가 저장된 열을 다시 읽을 때와 **같은 128값을 같은 레인에** 받으므로 `amax` 리덕션이 같은 집합 위의 같은 분할이고, 본체는 여전히 소유자 하나를 지난다. MoE 양자화 둘은 shexp `gate_up`을 앞으로 옮겨 인접시킨 뒤 두 기하를 한 런치로 돌린다.

그래프 **701 → 648노드.** 같은 프로세스·한 임대·팔을 회전시키는 A/B 여덟 바퀴(라운드간 SD 0.13~0.15%):

| 레버 | 층당 | 스텝 |
|---|---:|---|
| kqvc를 flash 안으로 | 1.18 µs/층 (27층) | −31.9 µs |
| MoE 양자화 둘 병합 | 1.38 µs/층 (26층) | −35.9 µs |
| 둘 다 | | **−69.3 µs** |

31.9 + 35.9 = 67.8이 동시 제거 69.3과 2% 안에서 맞는다 — 독립적인 런치 제거라면 가산적이어야 하고, 그렇다.

**둘 다 노드값 0.80보다 크다.** 레버 1은 노드를 지우는 데 더해 양자화기가 `kqvc`를 전역에서 **다시 읽던 왕복**을 없앤다(값이 이제 레지스터에서 공유메모리로 온다). 레버 2의 초과분은 가설이다 — 작은 그리드 둘(블록 66개와 22개)이 인접 노드로는 직렬로 돌다가 한 그리드 88블록 안에 숨는다는 것. **재지 않았다.**

| | p50 ms | tok/s | 대 ik 216.6 |
|---|---:|---:|---|
| 전 | 3.8919 | 256.94 | 1.186× |
| 후 | **3.8251** | **261.43** | ~~1.207×~~ → **1.199×** |

**정정(같은 날 새벽, 깊이 라운드가 찾음).** 이 "대 ik" 열은 **토큰 창이 어긋나 있다** — 우리 값은 `-n 32`이고 ik의 216.6은 n=96이다. 창을 ik 쪽에 맞추면 같은 구성이 258.81 대 215.82 = **1.199배**다. 스텝 p50과 계열 비교는 그대로 유효하고, 어긋남의 크기는 0.7%p, 방향은 우리에게 유리한 쪽이었다. 그리고 이 숫자는 **깊이 0의 문장**이라 깊이 4096에서 0.912배로 뒤집힌다 — [09-22-c](2026-09-22-c-the-headline-inverted-at-depth-4096.md).

리드 측정, 임대 아래, 증인 전후 깨끗. 게이트 여덟 재실행 rc 0, 새 계약 둘(접힌 양자화가 독립 런치와 비트 동일, 두 병합 각각이 대체한 런치 모양과 비트 동일)도 초록.

## 계측기를 고쳤다

앞 라운드가 찾은 결함 — 커널 벤치가 가중치를 0으로 채워 먹여 소프트웨어 디코드가 싸게 읽히던 것 — 을 고정 패턴으로 닫았다. 실측 크기는 Q4_K 2048×2048에서 **3.5%**다. 설명이 로그 속 주장으로 남지 않도록 `zerow` 대조 팔을 **상설로** 뒀다: 이제 매 실행이 같은 형상을 두 번, 영 가중치와 패턴 가중치로 찍는다.

`--profile`의 FFN 절반 분할도 리터럴 10/4에서 앵커·종단 이름 기반 유도로 바꿨다. 반쪽 안에서 런치가 합쳐져도 측정 도중에 터지지 않는다.

## 핀 셋, 이번엔 전부 빨강을 봤다

19 → 18, 24 → 22, 701 → 648. 셋 다 날짜 귀속 + 유도 + **관측된 빨강**이 붙어 있다. 두 라운드 전에 `NODES_CHAIN`만 유도로 내리고 "증거의 급이 다르다"고 적어 둔 빚도 이걸로 갚았다.

리드가 손본 것 둘. `split_kqvc` 레버는 접힌 뒤에는 쪼갤 pair 런치가 없어 **단독으로 조용한 no-op**이 됐다 — 다음 라운드가 "레버가 망가졌다"로 읽을 모양이라 그 조합을 거부하게 했다. 그리고 게이트 주석이 "`split_heads` + `split_flash_quant`면 755로 돌아온다"고 적었는데 재 보니 **702**다. 레버가 중첩돼서 원래 755에는 넷이 다 필요하다: 없음 648 / +heads+flash **702** / +kqvc 729 / +moe **755**. 관측값으로 고쳤다.

## 정직하게 남길 셋

shexp `gate_up`의 자리 이동에는 **비트 단위 증인이 없다.** 두 A/B 팔 모두 새 순서를 쓰기 때문이다 — 중립성은 별칭 논증(입력은 `act_ffn`뿐, 출력은 `h_sh`뿐)과 탭 밴드·e2e 분류가 한 자리도 안 변했다는 관측에 기댄다. 옛 순서는 바이너리에 없다.

장벽 0.72는 **바닥**이다. 그리고 `--time`에는 워밍 라운드가 없어 같은 바이너리의 `--ab` base보다 4.4% 느리게 읽는다 — 클럭 램프가 유력하나 재지 않았다. 오늘 밤 헤드라인은 전부 같은 계기라 계열 비교는 서지만, **ik 대비 비율은 그만큼 보수적**이다.

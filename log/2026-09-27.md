켬/끔은 lcg P 4096에서 1.373이었고 주 항 P 512는 판정하지 못했다. 호스트의 routed gate·up을 r8 사이드카(행-레인 타일로 다시 쓴 별도 파일)에서 읽으면 프롬프트가 예측만큼 빨라지는지, 같은 바이너리의 켬·끔 여덟 팔을 목록 384로 두 라운드 쟀다.

## ik DSpark 드래프트의 SwiGLU clamp (ik_llama.cpp#2546)

ik main에서 `swiglu_limit()`이 dflash arch에 0을 돌려줘 DSpark 드래프트 FFN이 clamp 없이 돈다. 참조 `model.py`와 exllamav3는 드래프트에도 건다. 한 줄 수정 전후와, 한계를 1e30으로 줘 clamp가 안 걸리는 control을 A6000에서 프롬프트 20개로 돌렸다.

| 모델 | 팔 | n_max 3 수락 | n_max 5 수락 |
|---|---|---|---|
| V4.1 Q3_K_M + DSpark 드래프트 | base | 1984/3417 = 58.1 % | 2137/4912 = 43.5 % |
| | control | 58.1 % (20/20 같음) | 43.3 % |
| | patch | 2023/3472 = 58.3 % | 2170/4764 = 45.5 % |
| V4 UD-Q3_K_M + V4 드래프트 | base | 2120/3480 = 60.9 % | 2278/4886 = 46.6 % |

V4.1에서 clamp는 20개 중 16개 프롬프트의 드래프트를 바꿨지만 n_max 3 차이는 +0.2 pp [−2.2, +2.1]로 0과 구별되지 않는다. n_max 5의 +2.0 pp도 부호 검정이 유의하지 않다(p = 0.42). 예측 +1…+6 pp는 빗나갔고, 틀린 것은 "걸리면 수락이 오른다"는 사전값이다. V4 드래프트에는 clamp가 한 번도 걸리지 않았다. V4.1 base는 [09-25 재측정](2026-09-25.md#ik-dspark-not-lossless)과 같다. PR은 참조와 맞추는 수정으로 냈다.

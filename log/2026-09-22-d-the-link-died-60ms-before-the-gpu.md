# 링크가 GPU보다 60 ms 먼저 죽었다

*2026-09-22 01:51 KST.* 깊이 측정 라운드가 본 표를 다 뽑고 **보조** 계기 비교를 돌리던 중, 3090이 사라졌다. `nvidia-smi`가 GPU0의 디바이스 핸들을 못 잡고, 드라이버는 복구 조치를 **두 카드 모두에** `OS Reboot`으로 올렸다.

## 커널이 적은 순서

60 ms 안에 다 들어 있다.

| 커널 시각 | 사건 |
|---|---|
| `320639.082828` | APEI 하드웨어 에러 — 심각도 **corrected**, PCIe, `port_type 4`(루트 포트), `device_id 0000:40:01.1`, `secondary_bus 0x41` |
| `320639.082933` | `pcieport 0000:40:01.1` AER — `aer_status 0x00000040`, `aer_layer=Data Link Layer`, `aer_agent=Receiver ID` (`BadDLLP` 1) |
| `320639.142553` | `NVRM: Xid (PCI:0000:41:00): 79, GPU has fallen off the bus` |
| `320639.142824` | `NVRM: Xid 154`, 복구 조치 `None → OS Reboot`, `0000:41:00`과 `0000:61:00` 둘 다 |

`secondary_bus 0x41`이 3090이다. **그 카드로 가는 링크가 정정 가능한 데이터 링크 계층 오류를 먹었고, 60 ms 뒤에 GPU가 없어졌다.**

## 귀속

증거는 우리 커널에서 멀어지는 쪽을 가리킨다. Xid 79는 링크·전원 계열 이벤트이고, 잘못된 커널의 불법 주소는 Xid 13/31로 나온다. 이 부팅의 Xid 31은 하나뿐인데 10시간 전 `0000:41:00 pid=85929 name=llama-cli`, 즉 ik지 우리가 아니다. 무엇보다 **커널 결함은 루트 포트에 Data Link Layer AER을 만들지 못한다.**

배제하지 못하는 것도 적는다. n=1이고, 카드가 돌아오기 전에는 재현할 수 없고, 같은 스윕의 증인 행에 306.62 W가 있으니 런치 형상이 전원 트랜지언트를 불렀을 가능성이 완전히 사라진 것은 아니다.

**전례가 있다.** 같은 카드가 2026-09-16 DDP 훈련 중 같은 Xid 79로 떨어졌고(WKS-31), 그때도 Xid 154가 두 카드에 걸렸다. 그 이슈는 아직 To Do이고 후속 항목이 하나도 실행되지 않았다.

다만 이번 부팅의 패브릭 소음은 그때와 다르다. 부팅 이후 AER 154건 중 **152건이 NVMe `0000:2b:00.0`**(Physical Layer, Receiver ID)이고 — 유휴 시간대까지 하루 종일 들어온다 — 3090 루트 포트의 것은 **이 사고에서 나온 2건뿐**이다. 09-15의 그 부팅은 A6000 루트 포트에 1891건이 쌓여 있었다. 이번 부팅에서 시끄러운 링크는 NVMe 쪽이었고, GPU 패브릭은 죽기 직전까지 조용했다.

## 사고 시점 링크 상태 (재부팅 전에 읽음)

| 장치 | LnkCap | LnkSta |
|---|---|---|
| `0000:40:01.1` 3090 루트 포트 | 16GT/s x16, ASPM L1 | **2.5GT/s** x16 |
| `0000:61:00.0` A6000 | 16GT/s x16 | **2.5GT/s (downgraded)** x16 |
| `0000:41:00.0` 3090 | — | 설정 공간을 못 읽는다, 장치가 없다 |

둘 다 2.5 GT/s인데 **이것을 결함이라고 부르지 않는다.** 카드가 유휴였고 ASPM L1이 광고돼 있으니 정상적인 유휴 강등일 수 있다. WKS-31이 같은 질문을 했고 아직 답이 없다 — 부하 중에 읽어야 갈리고, 그러려면 카드가 돌아와야 한다.

## 한 것과 하지 않은 것

**한 것**: 드라이버가 모듈 언로드 전에 받으라고 하는 `nvidia-bug-report.sh`를 받았다(박스의 `/root`에, 916,695 B). 호스트명이 들어 있으므로 이 리포에 넣지 않는다. 그리고 재부팅이 지울 증거 — AER 카운터, 링크 상태, dmesg 창 — 를 먼저 읽어 두었다.

**하지 않은 것: 재부팅.** 사용자가 자고 있고 원격 기계다. 안 올라오면 사용자는 아침에 기계 자체를 잃는다. 그리고 재부팅이 오늘 밤 사 줄 것이 없다 — GPU로 할 일은 이미 끝났다(A3 종료, 깊이 표 완료). 위험은 0이 아니고 이득은 0이면 안 하는 쪽이다. 판단은 사용자 몫으로 남긴다.

## 남은 것

WKS-40에 올렸고 WKS-31에 연결했다. 재부팅 뒤 할 것 다섯: ① **부하 중** LnkSta를 두 카드에서 읽어 2.5 GT/s 질문을 닫는다 ② `pcieport 0000:40:01.1`의 `BadDLLP`가 부하에서 오르는지 본다 ③ NVMe의 152건은 같은 패브릭의 별개 증상이라 따로 본다 ④ GPU 디코드 행 하나를 재현해 오늘 밤의 240.16 → 261.43 계열에 붙은 별표를 뗀다 ⑤ 그래도 재발하면 카드와 라이저를 다시 앉히고 BIOS Gen3 고정을 검토한다.

④ 전까지 2026-09-21/22의 GPU 수치는 전부 별표를 달고 읽는다.

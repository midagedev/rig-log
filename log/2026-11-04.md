# 2026-11-04

DGX Spark 엔진 비교의 밤 작업이다. 사용자가 자는 동안 큐 셋으로 남은 엔진 행을 돌렸고, Qwen3.6에서 bloomery가 MTP로 지는 자리를 nsys로 나눴다. 긴 표와 커널 이름은 [`docs/spark-engines.md`](../docs/spark-engines.md)에 있다. 드라이버는 580 그대로이고, 커밋은 아직 밀지 않았다.

<a name="spark-mtp36-split"></a>
## Qwen3.6 MTP가 bloomery를 늦추는 두 자리

MTP 층이 든 `UD-Q4_K_M`에서 MTP를 켜면 bloomery의 pp4096이 4,296에서 2,484로 떨어진다(−42 %). llama.cpp는 −7 %다. 디코드는 llama.cpp가 코드 +46 %를 얻고 bloomery는 +11 %다.

| 자리 | nsys가 보인 것 | 크기 |
|---|---|---:|
| 프리필 저장 걷기 | `q8_0_gemv` 16,800회(행당 4), `mtp_input` 4,200회. 프롬프트 행마다 디코드 모양 gemv | +470 ms / 4,200토큰(커널 합 +548 ms) |
| 디코드 창 | 검증 헤드 Q6_K를 행마다 따로 2번(1.87 ms씩), 드래프트 전체 어휘 헤드 1.85 ms, 2행 f32 `f32_tile_gemm` 1.3 ms | 창 25.0 ms(폭 0이면 15.3) |
| 디코드 폭 | `mtp_chain`이 자기 행을 거절해 제안이 늘 한 토큰. 걷기는 eager이고 그래프에 안 잡힌다 | llama.cpp n-max 3: 코드 96.9 vs 73.7 |

제안 1은 저장 걷기를 ubatch GEMM으로 바꾸는 것이다(`crates/gpu/src/arch/qwen3moe/mtp35.rs`). pp4096이 약 4,100(+65 %)으로 돌아온다고 계산한다. Atlas의 MTP 드래프터 프리필이 4,505위치에 136 ms라는 것이 한 번에 넘기는 길의 증거다.
제안 2는 체인 폭 2–3과 그래프 캡처, 3은 헤드 두 번 읽기를 한 번으로 줄이는 것과 줄인 어휘 드래프트 헤드다. 셋 다 bloomery 소스 빌드로 확인하지는 않았다.

<a name="spark-q38-width-cap"></a>
## Qwen3.8 MTP가 폭 3에서 멈춘다

TensorFold 1.2.1이 자기 MLX 4-bit MTP 판에서 Qwen3.8 코드 디코드 74.4 tok/s를 냈다. bloomery FP4-Local rec는 63.9다. MTP를 끄면 둘 다 약 29다(29.3 대 29.6). 그러니 차이는 MTP 쪽이다.

| | 라운드(창)당 토큰 | 수락률 | 창 비용 |
|---|---:|---:|---:|
| TensorFold, 코드 | 약 4.7 | 약 73 % | 약 63 ms |
| bloomery, 코드(폭 3) | 3.3–3.6 | 0.93–0.97 | 53–55 ms |

bloomery는 드래프트를 거의 다 맞히는데도 셋에서 멈춘다. `crates/runtime/src/stores.rs`의 `DELTA_VERIFY_ROWS = 4`(gated-delta 층 검증 기록이 4행까지)와 폭 선택기의 4칸 배열이 상한이다.
제안: 상한을 6으로 올리고 폭 5까지 고르게 한다. 폭당 창 비용 증가(8 → 7 → 5 ms)로 추정하면 코드 디코드는 약 83 tok/s(+30 %)이고, 산문은 선택기가 폭 2를 고르니 그대로다. 소스 빌드로 확인하지는 않았다.
프리필은 bloomery가 앞선다(pp4096 2,330 대 1,503).

## Qwen3.6 Q4_K_M 두 파일과 테이프 대조

juliankang4의 테이프는 lmstudio `Q4_K_M`이고, 우리 보드 2는 unsloth `UD-Q4_K_M`이다. 밀집 텐서가 lmstudio는 K-quant 860 MB, unsloth는 Q8_0 1,525 MB다. 토큰당 읽기가 약 1.9 GB와 2.6 GB로 다르다.

| lmstudio `Q4_K_M` | 코드 | 산문 | pp512 | pp4096 |
|---|---:|---:|---:|---:|
| bloomery 0.3.12 | 92.0 | 92.7 | 2582 | 4549 |
| llama.cpp b12069 | 76.7 | 77.5 | 1919 | 2415 |

bloomery는 두 파일에서 실효 대역폭이 같다(약 174 GB/s). llama.cpp는 unsloth 파일에서 176, lmstudio 파일에서 146 GB/s다. 그러니 unsloth 파일에서 둘이 비기는 것은 llama.cpp의 Q8_0 경로가 강해서다.
toktape(prompts@v2, 세 번)로는 bloomery가 디코드 80.7–81.1, 프리필 4,779–4,827이다. 테이프의 86.9 / 4,301(0.3.0, 드라이버 595.84, 2슬롯)과 비교하면 디코드는 −7 %, 프리필은 +12 %다. 판과 슬롯을 가르는 시험(0.3.11, `--parallel 2`)은 큐에 있다. 드라이버는 바꾸지 않는다.

## 밤에 채운 엔진 행

남은 엔진을 한 번에 하나씩 돌렸다. 전체 표는 [`docs/spark-engines.md`](../docs/spark-engines.md)의 "아침 요약"이다. 클라이언트 시계, tok/s, 디코드 코드 / 산문.

| 엔진 · 파일 | MTP 켬 | MTP 끔 | pp4096(켬) |
|---|---:|---:|---:|
| Flare · Qwen3.8 FP4-Local | 47.5 / 36.8 | 26.7 / 27.0 | 2232 |
| bloomery · 같은 파일 | 63.9 / 42.9 | 29.6 / 29.8 | 2330 |
| SGLang · Qwen3.8 NVIDIA NVFP4(N-gram 표 NVMe) | 30.2 / 21.5 | 15.2 / 14.9 | 1598 |
| Strata · Qwen3.8 IQ3_S | 66.8 / 49.6 | 31.7 / 34.5 | 1577 |
| llama.cpp · 같은 IQ3_S | | 30.9 / 31.1 | 752 |
| Atlas · Qwen3.6 NVFP4(MTP K=1) | 141.2 / 123.6 | 95.8 / 96.4 | 2628 |

Flare는 무인 첫 실행에서 패키지 키 승인을 요구해 한 번 거절됐다. 키는 우리가 내보낼 때 만든 로컬 개발 키라서 지문을 확인하고 넘겼다.
SGLang의 한 대 셀은 쿡북이 적은 값(27.5 / 15.9)과 맞는다. 부팅마다 47.7 GiB 표 파일을 새로 써서 11–13분 걸린다.
Strata는 Qwen3.8에서는 MTP가 듣는다(Qwen3.6에서는 효과가 없었다). 같은 GGUF에서 llama.cpp보다 pp4096이 2.1배다.
Atlas는 폭 1 MTP로 코드 +47 %를 얻는다. bloomery는 같은 폭에서 +11 %다. 폭 1 창이 bloomery에서 평 걸음의 1.63배라서다.
bloomery는 IQ3_S(공유 전문가 IQ4_NL)와 Qwen3.6의 NVFP4·FP8·MLX 폴더를 열지 않는다. 그 칸에는 bloomery 행이 없다.

## bloomery 소스 빌드로 잰 두 제안

CUDA 13.3 devel 컨테이너에서 bloomery v0.3.12를 빌드했다. 호스트 드라이버 580과 커널은 건드리지 않았고, 13.3 바이너리는 580에서 그대로 돌았다. 패치는 Spark의 스크래치 클론에만 했다.
Qwen3.8 FP4-Local, MTP `cost`, 행마다 두 번, 무패치 `base` 빌드 대비.

| 제안 | 추정 | 잰 값 |
|---|---|---|
| 검증 4 → 6행, 폭 5 | 코드 +30 % | 코드 +8.6 %(63.5 → 69.0), 산문 −2.5 % |
| `MTP_STORE_ROWS` 512 | pp4096 +3.5 % | pp4096 +2.6 % |

폭 5는 고르지만 창 비용이 행마다 약 6.5 ms 늘어 이득이 줄었다. 패치하려면 `place.rs`의 아레나 상수도 함께 고쳐야 한다. 첫 빌드는 그 검사에서 로드를 거절당했다.
Atlas를 nsys 아래 다시 돌리는 일은 두 번 실패했다. 첫 번째는 빌드와 겹쳐 watchdog이 서버를 죽였고, 두 번째는 프로브가 `model` 필드를 보내지 않아 거절됐다. 자세한 것은 [`docs/spark-engines.md`](../docs/spark-engines.md)의 "소스 빌드로 잰 제안 ②⑦"에 있다.

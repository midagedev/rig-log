# 생성 모델의 프롬프트 작성

이미지·영상 생성 모델에 먹일 프롬프트를 사람이 직접 쓰는 일에 관한 문서.
2026-10-03 Qwen-Image-2.1 첫 시팅([기록 전 단계: 러너 `tools/comfy/qwen21-first-sitting.sh`, 커밋 975f038](https://github.com/midagedev/rig-log/commit/975f038))에서
공식 ComfyUI 템플릿을 API 형식으로 펴다가 얻은 발견이 출발점이다.
측정 숫자는 이 문서에 두지 않는다 — 로그의 몫이다.

## 발견: 프롬프트 작성은 별도의 추론 단계다

Qwen-Image-2.1은 이미지 모델과 함께 **프롬프트 재작성 전용 LLM**을 배포한다.
Comfy-Org 리팩 리포의 `text_encoders/qwen3.5_9b_qwen_image_2.1_pe_t2i.int8_convrot.safetensors`
(9.5 GB, 원본 `Qwen/Qwen-Image-2.1-PE-T2I`·`PE-I2I`)가 그것이고, 공식 t2i 템플릿은
이를 `TextGenerate` 노드에 태워 사용자의 짧은 브리프를 먼저 다시 쓴 다음 이미지
모델에 먹인다. 텍스트→이미지와 이미지→이미지용 두 가지가 따로 있다.

생성 모델과 프롬프트 작성기가 같은 릴리스 안에 나온다는 것은, 프롬프트 작성이
사용자 기술이 아니라 **파이프라인의 선행 추론 단계**로 취급된다는 업계 합의로
읽는다. 템플릿 기본값은 끄기(빠름, 통제)지만 공식 안내는 켜면 대체로 품질이
오른다고 한다.

## 그 시스템 프롬프트가 규정한 장인기술

재작성기의 시스템 프롬프트는 공식 템플릿 JSON 안에 통째로 들어 있다
([템플릿 원본](https://github.com/Comfy-Org/workflow_templates/blob/main/templates/image_qwen_image_2_1_t2i.json)).
"관찰자가 완성된 그림을 보고하는" 8단계 절차인데, 규칙 중 결정적인 것만 옮기면:

- **고정과 자유를 먼저 가른다.** 사용자가 준 텍스트 문자열·개수·색·위치·비율은
  한 글자도 바꾸지 않고 생존시킨다. 나머지는 재작성기가 발명한다.
- **프레임을 지역으로 걷는다.** 배경 → 상단 띠 → 좌·중·우 → 하단 띠. 문장의
  3분의 1은 위치 구문으로 시작해 모서리·가장자리·중앙이 골고루 닿게.
- **그림 속 텍스트는 읽는 순서대로, 원래 문자 그대로.** 한국어는 한국어로.
  크기·색·활자 무게를 붙이고, 안 읽히는 표지는 "흐릿하다"로 둔다.
- **조명에 독자 문장 하나, 전체 구도로 닫는 문장 하나.**
- **품질 부스터 금지.** 걸작·8K·고해상도 같은 말은 쓰지 않는다. 관찰 보고이지
  지시가 아니다. 애매한 것은 애매하게("나무 또는 짙은 라미네이트") 표현한다.
- **분량은 브리프 길이와 무관하게 약 400–500 영어 단어.** 세 단어 브리프도
  같은 크기의 묘사가 나온다.

## 왜 긴 묘사인가

요즘 DiT 계열 모델은 긴 리캡션(caption)으로 학습되어, 짧은 수동 프롬프트는
모델 용량을 덜 쓴다. 이 기계의 기록에도 같은 구조의 실패가 있다 — 09-16의
["거대 고양이가 빠진 클립"](../log/2026-09-16.md#what-guidance-was-not-for)은
파이프라인 탓으로 좁혔다가 프롬프트 구조 문제로 정정했다. 프롬프트가
수동형("메카를 그려줘")이냐 관찰형("오른쪽 상단에 메카의 어깨가…")이냐의
차이가 결과의 내용을 바꾼다는 뜻이다.

## 이 기계에서 하는 두 가지 방법

1. **워크플로 안(템플릿의 설계)**: PE 체크포인트(int8 9.5 GB)를 받아
   `TextGenerate` 노드를 켠다. 같은 카드에서 LLM 한 번 → 이미지 모델.
   `thinking_mode`는 켜는 것이 공식 권장(추론 블록 없이 학습돼 없으면 품질이
   떨어진다). 아직 내려받지 않았다.
2. **서빙 LLM으로**: 이 기계에 상주 가능한 V4.1·GLM 등에 위의 시스템 프롬프트를
   그대로 얹으면 프롬프트 작성기가 된다. `tools/ltx/llm-chain-s.sh`가 이미 LLM을
   같은 축으로 재던 전력이 있고, signalbox의 `/gen/*` 앞단에 enhance 단계를 다는
   확장이 자연스럽다.

## 측정과 창작을 가르는 선

재작성기는 온도가 있는 추론이라 같은 브리프가 매번 다른 프롬프트를 만든다.
그래서:

- **잴 때는 끈다.** 첫 시팅도 `refine_prompt` 끈 상태에서 손 쓴 프롬프트로
  돌렸다. 숫자의 재현성이 프롬프트 무작위성에 묻히면 안 된다.
- **창작에서는 켠다.** 다만 "고정 생존" 규칙이 지켜지는지 산출물로 확인한다.
- LLM을 앞단에 쓸 때 모델 간 격차는 번역 실험(09-18: 가장 빠른 것이 가장
  정확한 것의 네 배로 틀렸다)의 교훈이 그대로 적용된다.

## 다음 실험 후보

같은 시드·같은 브리프로 (a) 손 프롬프트, (b) PE 노드, (c) 서빙 LLM + 이 시스템
프롬프트의 세 산출물을 나란히 돌려 재작성 단계의 효과를 이 기계에서 잰다.
재작성 프롬프트 자체도 산출물로 보관할 것 — 입력이 같았다는 증거가 프롬프트다.

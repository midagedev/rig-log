# 릴리즈 영상 런북

bloomery 릴리즈마다 만드는 40–55초짜리 홍보 영상을 만드는 순서다. 0.3.11·0.3.12·0.3.14·0.3.15 영상을 만들면서
틀렸던 것을 모아 정했다. 실제로 쓰는 도구는 [`tools/film/`](../tools/film/)에 있다. 에이전트는
[`skills/release-film/SKILL.md`](../skills/release-film/SKILL.md)로 이 런북을 연다.

## 누가 무엇을 하나

- **리드(메인 세션)**: 사실값을 넘기고, 박스 녹화를 돌리고, 라운드 보고를 검토하고, Drive에 올리고, 사용자에게 링크를
  준다. 영상 내용(장면 문구, 타이밍, 디자인)은 직접 손대지 않는다. PNG도 직접 읽지 않는다.
- **opus 라운드**: 디자인, 장면 작성, 비전 자기 검사를 맡는다. 볼 일이 있는 라운드라서 opus다. 라운드 하나가 단계
  하나를 끝내고 물러난다.
- **사용자**: 스타일 시안을 고른다. 최종본을 본다. 영상을 공개할지 정한다.

## 순서

### 0. 스타일 시안 먼저 (렌더 전에 반드시)

숫자와 감사가 다 맞아도 모양새가 낡아 보이면 실패다. 0.3.11은 "20세기 느낌, 3D 느낌", 0.3.15 v2는 "2020년에
만든 영상 같다"는 말을 들었다. 그래서 렌더보다 먼저 이 단계를 한다.

1. opus 라운드가 최근 1년 안의 제품 런칭 영상과 페이지를 여섯 개 이상 조사한다. 개발 도구, AI 모델, 하드웨어
   발표가 대상이다. 출처마다 URL을 실제로 열어 한 줄을 옮기고, 타이포·모션 곡선·색과 빛·밀도·전환과
   터미널·숫자 표를 보여 주는 방식을 2–3개씩 적는다. 출처 없는 특징은 쓰지 않는다.
2. 지난 릴리즈 영상의 스틸 중 어떤 것이 낡아 보이는지, 대조되는 출처의 특징과 짝지어 진단한다.
3. 방향을 세 개 낸다. 3D와 레트로는 뺀다. 방향마다 규칙 다섯 개(타이포, 색과 빛, 모션, 레이아웃, 터미널과
   표)를 정하고, 프레임 세 장(타이틀, 성능 표, 코딩 장면)과 3초 모션 테스트를 만든다.
4. 컨택트 시트 한 장과 HTML 페이지 하나로 사용자에게 보여 준다. 사용자가 고른 방향이 그 릴리즈와 다음 릴리즈의
   기준이 된다. 고른 방향과 규칙은 이 런북의 「현재 스타일」 절에 적는다.

### 1. 종이 먼저

- 음악 트랙의 박자가 모든 길이를 정한다. 장면 길이는 박자 수로 정하고, 8박 단위로 늘리거나 줄인다.
  [`tools/film/recut.py`](../tools/film/recut.py) `--measure`로 이음매 후보를 재고 dBFS가 가장 낮은 것을 고른다.
- 장면 표를 쓴다. 장면마다 박자 수, 초, 길이를 정한 이유를 적는다. 표 장면은 정지 상태로 4.5초 이상 둬야 읽힌다.
- 렌더 시간을 예측한다. Mac CPU만 쓴다. Chromium 래스터와 PNG 인코딩을 페이지 4개로 돌리고, 이어 x264를 돌린다.
  세 단계를 차례로 돌리니 전체 시간은 세 시간의 합이다. 3,000프레임에 7–8분이다.

### 2. 사실 출처 한 파일

- 화면에 나오는 숫자와 주장은 모두 `facts-source.md` 한 파일에서 온다. 릴리즈 시팅 값을 그대로 옮기고, 조건(카드,
  P, depth, 바이너리 커밋)을 붙인다.
- 감사(audit)가 화면의 모든 숫자를 출처와 대조한다. 출처에 없는 숫자, 금지어, 다른 추론 엔진 이름이 화면에 있으면
  감사가 rc 2로 막는다.
- 이슈를 보고해 준 사람은 감사 장면과 릴리즈 노트에 이름을 넣는다.

### 3. 박스 녹화 (리드)

- 두 모델이 같은 과제를 하는 장면은 [`tools/film/kit/record.sh`](../tools/film/kit/record.sh)로 박스에서 녹화한다.
  카드에는 한 번에 한 모델만 올린다. 에이전트는 systemd-run 울타리 안에서 돈다. 네트워크는 loopback만, 다른 엔진은
  보이지 않게 한다. 로깅 프록시가 요청과 답을 모두 남기고, 끝나면 `film.json`과 페이지 루프 프레임을 쓴다.
- 과제 문구는 [`kit/prompt.txt`](../tools/film/kit/prompt.txt)다. 이미 있는 게임이나 제품을 다시 만드는 과제는
  안 된다. 이름(아카노이드, 브레이크아웃 같은 것)도 화면이나 코드에 나오면 안 되고, 감사가 `GAME_NAMES`로 막는다.
- 녹화 전에 과제 시간을 예측해 출력한다. 계산은 T = (P0 + 요청마다 캐시 안 된 토큰 합) / prompt rate + 출력 토큰 /
  decode rate다.
- 서빙 장면은 toktape 테이프와 서버 로그를 쓴다. 테이프는 릴리즈 후보 바이너리로 찍는다.

### 4. 장면 작성 (opus 라운드)

- HTML/CSS/JS 한 페이지를 headless Chromium으로 1920×1080에서 프레임마다 찍는다. 시계는 가짜 시계 하나를 앞으로만
  돌린다.
- 코딩 장면은 에이전트 세션 기록(`session.v4.jsonl.zstd`)을 그대로 재생한다. 모든 글자는 기록에서 오고, 색만
  입힌다. 두 패널은 한 배속으로 같은 시계를 쓰고, 화면에 "replayed at ×N"과 run clock을 보인다.
- 폰 크기에서 읽혀야 한다. 터미널 글씨 하한은 22px이다.

### 5. 감사와 FAIL-first

- `REQUIRE_REAL=1 DSH_JSON=<run>/film.json ./refacts.sh`가 사실 파싱, 감사, 프레임, 인코딩, 음악 검사까지 한 번에
  돈다. rc 65는 입력이 없다는 뜻이고, rc 2는 감사가 찾은 것이다.
- `mutants.sh`가 일부러 망가뜨린 버전(숫자 하나 바꾸기, 금지어 넣기, 배속 바꾸기 등)이 모두 빨갛게 되는지 본다.
  빨갛게 안 되는 mutant가 있으면 그 감사는 믿지 않는다.
- [`tools/film/beatcheck.py`](../tools/film/beatcheck.py)가 완성된 mp4의 소리에서 박자를 다시 찾는다. 장면 전환이
  한 프레임(16.7ms)보다 박자에서 멀면 rc 2다.

### 6. 비전 자기 검사

라운드가 장면마다 처음·중간·정지·끝 프레임과 모션 시트를 직접 열어 장면 계약과 맞춰 보고, 찾은 것과 고친 것을
LOG.md에 남긴다. 축마다 SHIP/FIX 예측을 적는다. 리드는 그 텍스트 판정만 읽는다.

### 7. 올리기

- `gog drive upload <mp4> --name bloomery-<버전>-release-<길이>s.mp4 -j`로 올린다. 이름은 `bloomery-`로 시작한다.
- 결과의 `size`가 로컬 바이트와 같은지 확인하고, `webViewLink`를 사용자에게 준다.
- 공개(트윗, README 링크)는 사용자가 정한다.

## 현재 스타일

**B · Grid** (2026-11-19 사용자 선택, 시안: promo0315style). 검은 바탕에 12×9 그리드가 보이게 깔리고, 장면이 바뀔 때
그리드가 다시 나뉘면서 다음 장면으로 이어진다. 숫자는 크고 가는 글자, 라벨은 대문자 mono, 강조는 화면당 하나다(그 행이나
칸을 ember 띠로 뒤집는다). 같은 슬라이드를 장면마다 다시 짜는 soft cut, macOS 창틀과 그림자는 쓰지 않는다.

사용자가 함께 정한 것:

- **폰에서 본다(트위터).** 작은 글씨가 화면을 채우면 안 된다. 1920×1080 기준으로 읽으라고 둔 글자는 44px 이상이고,
  한 화면에 읽을 덩어리는 셋 이하다. 흘러가는 코드처럼 질감으로만 두는 작은 글자에는 반드시 큰 캡션 하나가 붙는다.
  빽빽한 표는 한 화면에 몰아넣지 않고 행을 차례로 크게 보인다.
- **코딩 과정과 결과물을 충분히 보인다.** 영상이 길어져도 된다. 에이전트가 코드를 쓰고, 스크린샷을 보고, 고치는 순간을
  확대해 캡션과 함께 보이고, 결과물(만든 게임)은 화면을 크게 써서 1×로 몇 초씩 돌린다.
- **모션그래픽을 제대로 쓴다.** 전환은 끊지 않고 잇는다(그리드 재분할, 숫자 카운트, 키네틱 타이포). 곡선은 이징을 쓰고,
  움직임마다 이유가 있다.

## 함정

| 증상 | 원인 | 막는 법 |
|---|---|---|
| 게임 화면이 좌우로 뒤집히듯 깜빡인다 (0.3.15) | `shot.mjs` 루프가 프레임마다 새 페이지를 열어, 매 프레임이 `Math.random`이 다른 새 게임이었다 | 페이지 하나, `page.clock.install` 하나, `clock.runFor`로 앞으로만 돌린다 (지금의 `kit/shot.mjs`) |
| 90프레임마다 루프가 튄다 (0.3.11) | 샤드마다 페이지 시계를 다시 시작했다 | 시계 하나로 전체를 렌더한다 |
| 스케일한 루프의 첫 프레임이 깨진다 | ffmpeg image2의 기본 시작 번호가 1이다 | 양쪽에 `-start_number 0`, 48프레임이 f_000부터인지 검사한다 |
| 감사가 canvas를 못 읽는다 | file:// 프레임이 canvas를 tainted로 만든다 | Chromium을 `--allow-file-access-from-files`로 띄운다 |
| 감사가 그림 결함을 놓친다 | 텍스트를 행 모델에서 읽었다 | 그려진 DOM에서 다시 읽는다 (replay-tamper mutant) |
| 박스 headless Chrome에서 WebGL이 안 된다 | GPU 프로세스 분리 | `--in-process-gpu` |
| 영상이 낡아 보인다 (0.3.11, 0.3.15) | 렌더 전에 스타일을 사용자에게 보이지 않았다 | 0단계 |
| Drive 이름이 `gadak-`이었다 | 전역 규칙의 예시 이름을 그대로 썼다 | `bloomery-<버전>-release-<길이>s.mp4` |

## A. 출처가 말하는 것

### A1. 번역 피벗 캐스케이드

- **영어 잠재 언어 [1]**
  - Llama-2 7B/13B/70B에서 logit lens로 번역, 반복, cloze 과제를 봤습니다.
  - 앞 절반 층에는 정답도 영어 대응어도 확률이 없습니다.
  - 중간층에서 영어가 급상승했다가 줄고, 마지막 5층에서 중국어가 넘어섭니다.
  - 70B 번역은 1-40층 엔트로피 14 bit, 41-70층 영어 우세, 71-80층 중국어 우세입니다.
  - 학습 코퍼스의 89.70%가 영어입니다.
  - 저자 한계는 Llama-2 중심, 단일 토큰 장난감 과제, logit lens가 직교 성분을 못 본다는 점입니다.
  - 층별 확률은 그림에만 있습니다.
- **Schut [2]**
  - 생성 단어가 영어를 경유한 비율(표 3 평균)은 Gemma-2-27b 0.70, Mixtral-8x22B 0.68, Llama-3.1-70B 0.55, Aya-23-35B 0.50입니다.
  - 명사와 동사는 영어를 경유하고 전치사와 관사는 드뭅니다.
  - 동철자어는 구분할 수 없다고 저자가 인정합니다.
- **반대 근거의 핵심은 Wu [3]**
  - 허브는 지배 사전학습 언어에 고정됩니다. Llama-3의 중국어 입력은 17층 이후 영어 토큰에 가깝습니다.
  - 중국어 우세 Baichuan-2는 뒤집히고, BLOOM은 우세 언어가 없습니다.
  - 영어 잠재 언어는 구조가 아니라 학습 혼합의 사실입니다.
  - 영어 비중이 큰 모델은 바깥에서 무엇을 하든 영어를 경유합니다.
- **뉘앙스**
  - Dumas [4]는 개념 표현이 언어 무관하고 출력 언어가 개념보다 이른 층에 인코딩된다고 보고합니다. Wendler와 같은 그룹이고 "영어 쪽으로 치우친 개념 공간"과 양립합니다.
  - MoE 라우팅 [5]은 첫·끝 층이 언어별이고 중간층은 영어와 정렬됩니다. 영어와의 라우팅 발산은 Belebele 정확도와 상관이 있습니다.
  - 그 상관 r은 OLMoE -0.95~-0.80, GPT-OSS -0.40~-0.60입니다.
  - 영어 라우팅 조향은 MGSM 비영어 평균을 Qwen3 76.4에서 78.0, GPT-OSS 68.9에서 71.5로 올렸습니다.
- **번역 캐스케이드 품질**
  - MGSM PaLM-540B [6]: Native-CoT 48.1, EN-CoT 51.3, Translate-EN 55.0 (10개 언어, 한국어 없음).
  - ChatGPT 6개 NLP 벤치 평균, 고자원/저자원 [7 표 1]: Native-Basic 50.8/40.8, Trans-Google 61.4/59.0.
  - 요약 XL-Sum은 native 32.5/29.9가 Trans-Google 30.6/28.9보다 높습니다.
  - 중국어 중심 Qwen1.5-72B-Chat은 EN-CoT 65.7, Trans-Google 64.2, native 62.9입니다.
- **큰 모델에서는 번역이 집니다.**
  - PaLM2-L은 108개 언어 중 94개에서 직접 추론이 이깁니다 [8].
  - Belebele 정확도는 84.3에서 88.4, XLSum RougeL은 25.4에서 28.0입니다 (표 1).
  - 번역이 이기는 7개 언어는 모두 저자원입니다: Bambara, Quechua, Lingala, Oromo, Punjabi, Tigrinya, Tsonga.
  - 한국어는 이 목록에 없습니다. 번역기는 Google Translate API입니다.
- **문화와 한국어**
  - 저자들은 문화 과제에서 번역이 최적이 아니라고 씁니다. ShareGPT 질의의 30~74%가 문화 지식을 요구합니다 [7].
  - MMLU 문항의 28%가 문화 민감이고 모델 순위가 부분집합에 따라 바뀝니다 [9].
  - 한국 원문 시험 KMMLU [10]에서 GPT-4는 59.95입니다. 한국 문화 부분집합 KMMLU-KOR(1,305문)에서는 51.21입니다.
- **도구 호출, JSON, 보호 구간**
  - Arabic BFCL [11]은 5개 모델에서 질의를 아랍어로 쓰면 도구 호출 정확도가 평균 5-10% 떨어진다고 보고합니다.
  - 영어 질의가 350건 이기고 아랍어는 10건, 동률 32건입니다.
  - 도구 설명까지 아랍어로 번역하면 영어 설명이 322건 대 37건으로 더 낫습니다.
  - 오류 유형(인자값, 번역된 파라미터명, 음차)은 분석하지 않았습니다.
  - DeepL은 XML 모드에서 ignore_tags 내부를 번역하지 않습니다 [12].
  - 코드, 표, 고유명사가 번역에서 깨지는 비율을 잰 논문은 찾지 못했습니다.
- **출력 스트리밍과 지연 [13]**
  - Llama2-7B-chat SimulMT, MuST-C 영어에서 9개 언어, RALCP 정책 평균 BLEU 31.33, LAAL 7.62입니다.
  - 저자 판단은 LLM의 계산 비용이 적용의 큰 장애물이라는 것입니다. 한국어 쌍은 없습니다.

### A2. 전문가 가지치기

REAP [14] 표 3, A6의 값은 기준 / 25% / 50%입니다. 보정은 12,228샘플, 길이 16,384 이하이고 C4, evol-codealpaca, xlam, SWE-smith를 섞었습니다. 재학습은 없습니다.

|---|---|---|

| SWE-Bench Verified | .554 / .580 / .576 | .540 / .540 / .522 |

- **REAP 비교군**
  - 빈도 기준 가지치기는 K2 25%에서 Code Avg .284, 50%에서 .056입니다.
  - Qwen3-30B 50% Code Avg는 M-SMoE .397, HC-SMoE .364, REAP .541, 기준 .558입니다.
  - C4만으로 보정하면 코드가 무너져 일부 모델이 0%가 됩니다.
  - 다국어 평가와 한계 절은 없습니다.
- **top-k 재정규화는 논문마다 다릅니다.**
  - REAP은 분석식 2에서만 남은 K-1 전문가로 게이트를 재정규화합니다. 체크포인트 구현과 norm_topk_prob는 서술이 없습니다.
  - TransPrune [19]은 router weight와 bias를 슬라이스하고 활성 전문가 4개를 유지합니다.
  - AIMER [20]은 "remove the selected expert FFN parameters together with the corresponding rows in the router matrix"라고 쓰고, 남은 전문가 위에서 같은 top-k 규칙을 유지합니다. 별도 재정규화 단계는 찾지 못했습니다 (에이전트 판독).
  - Lu [15]는 제거한 전문가의 routing weight를 함께 버립니다.
  - HC-SMoE [16]은 라우터를 건드리지 않습니다.
- **Lu [15]**
  - Mixtral 8x7B(8전문가 top-2)를 C4 128×2048로 보정했고 방식은 열거입니다.
  - 8과제 평균은 67.58, 64.22(r=6), 59.57(r=4)입니다. MMLU는 67.88, 58.72, 47.30입니다.
  - 메모리는 89,926, 68,383, 46,879 MB입니다.
  - GSM8K 58.61은 C4 보정에서 41.02, MATH 보정에서 51.25가 됩니다.
  - 저자 한계: 전문가가 많으면 열거가 비현실적입니다.
- **병합**
  - HC-SMoE [16]은 재학습 없이 8 MC 평균을 Mixtral .6748, .6425(25%), .5729(50%)로 냈습니다. Qwen1.5-MoE는 .6008, .5716, .5223입니다. 생성 과제 평가는 없습니다.
  - MC-SMoE [17]은 SFT+KD 후 메모리 80%, FLOPs 20%를 줄입니다. 일부 과제 손실은 1% 미만이지만 SST-2 -2.40, WinoGrande -2.28입니다.
  - REAP [14]은 생성 과제에서 병합이 라우터의 독립 제어를 잃어 가지치기가 낫다고 주장합니다.
- **Koishekenov [18]**
  - NLLB-200 54.5B에서 전문가 1,536개 중 288개를 남겼습니다. 논문 표기는 80%이고 재학습은 없습니다.
  - 게이트 통계는 top1×exp(conf)입니다.
  - 53개 언어 chrF++ 평균(표 2): MoE 36.81, 언어별 가지치기 36.61, 언어 무관 공통 가지치기 35.34.
  - 디코더 전문가 유사도는 같은 목표 언어 68-87%, 다른 목표 언어 13-39%입니다.
- **TransPrune [19]**
  - GPT-OSS-20B(32전문가 top-4)를 라우팅 질량으로 가지치기했고, FLoRes dev 4개 언어로 보정했습니다.
  - xCOMET 5개 언어 평균(표 1): 기준 .942, 50% .930, 62.5% .896, 68.75% .859.
  - 10k 증류 SFT 후에는 68.75% .904, 75% .902, 87.5% .871입니다.
  - 비보정 언어(ru, es, zh)가 보정 언어와 같은 곡선을 따릅니다.
  - 벵골어와 이집트 아랍어는 회복이 덜합니다. k=22 En→X 손실이 -.073, -.106이고 평균은 -.053입니다 (표 5).
  - 번역 외 능력은 미평가입니다 (저자 한계).
- **AIMER와 Cerebras**
  - AIMER [20]는 보정 불필요 가중치 점수입니다 (EMNLP 2026 Findings). 기존 방법의 결정이 보정 데이터에 민감하다고 서술합니다.
  - Cerebras [21]에는 REAP 체크포인트가 30개 있고 K2, K3용은 없습니다.
  - DeepSeek-V3.2-REAP-345B-A37B(256에서 128 전문가) 카드는 LiveCodeBench 64.64, HumanEval 93.29, MBPP 91.01을 자체 보고합니다. 카드의 점수표에는 기준 열이 없고 MMLU도 없습니다 (카드 전문 5,710바이트 확인).
- **언어 특화 전문가**
  - OpenMoE [22]는 32전문가에서 도메인 특화가 약하고 언어 수준 특화는 뚜렷합니다. zh-cn, zh-tw는 E5·E16, ja·ko는 E14를 선호하고 라우팅은 토큰 ID에 좌우됩니다.
  - Mixtral [23]은 주제별 특화가 없고 구문 수준만 보입니다.
  - 조밀 모델 LLaMA-2 70B [24]의 언어별 특화 뉴런은 836(en)~6,154(es)개입니다. 중국어 뉴런을 끄면 zh 점수가 4.30에서 2.46으로 내려가고, 관련 언어(fr-es, zh-ja)만 함께 떨어집니다.
  - MoE [5]에서 모든 층의 다국어 전문가를 끄면 크게 하락합니다. 중간층 것은 상당수 꺼도 큰 하락이 없습니다 (수치 없음).
  - 끝 층에는 다국어 생성 전용 전문가가 있고 영어는 선택지가 더 넓다는 저자 문장이 있습니다.
- **버려진 언어:** 영어+코드로 보정한 뒤 제외된 언어의 일반 성능을 잰 출처는 찾지 못했습니다. 가장 가까운 것은 [19]와 [18] 항목입니다.

## B. 내 해석 (출처 없음)

- **종이 분해, 크기**
  - K3 HF API 합계 2,779,931,837,184 중 U8이 2,722,740,830,208이고 3×3584×3072×896×92와 정확히 같습니다.
  - 라우티드 전문가가 97.94%이고 나머지가 57.19B(2.06%)입니다.
  - 전문가를 비율 f만큼 지우면 파라미터가 0.979f 줄어듭니다. 25%는 24.5%, 50%는 49.0%입니다.
  - 594 GB는 평균 1.71 bit/param입니다. 비전문가를 2~16 bit로 가정하면 전문가 바이트가 480~580 GB입니다. 그러면 25%는 120~145 GB, 50%는 240~290 GB가 줄어듭니다. 정밀도 가정은 확인하지 않았습니다.
- **어휘는 파라미터 0.0845%지만 디코드 바이트로는 다릅니다.**
  - 헤드는 토큰마다 통째로 읽고, 라우티드 전문가는 16×92×33,030,144 = 48.62B 파라미터를 읽습니다.
  - 헤드 8/16 bit면 1.17/2.35 GB, 전문가 1.0/1.7 bit면 6.08/10.33 GB입니다. 헤드는 전문가 바이트의 11~39%입니다.
  - 분모가 전문가만이라 전체 대비로는 상한입니다.
  - 그래서 "어휘 다듬기는 작은 모델만 의미 있다"는 파라미터 비중으로만 참입니다.
  - 헤드가 카드에, 전문가가 호스트 DRAM/NVMe에 있으면 서로 다른 자원이라 그림자 아래일 수 있습니다. 자원별 시간을 먼저 그려야 합니다.
  - 한글 고유명사가 K3로 통과하면 한글 토큰이 필요합니다.
- **자원 타임라인 (요청 1건, 측정치 없이 구조만)**
  - 입력 번역은 카드 SM과 VRAM을 쓰고 K3 prefill 앞에 직렬입니다. 문장 단위로 prefill에 흘리면 겹칩니다.
  - K3 디코드가 지배 항입니다.
  - 출력 번역은 번역기 처리율이 K3 영어 토큰 생성률 이상일 때만 디코드 그림자 아래 숨습니다. 그러면 추가 지연은 마지막 문장 꼬리 하나입니다.
  - 번역기 가중치는 VRAM을 차지합니다. 4.3B 모델 [19 표 1]은 bf16으로 약 8.6 GB [derived]이고 K3의 카드 상주분과 경쟁합니다.
- **캐스케이드와 가지치기의 연결**
  - 모델이 한국어를 보지 않으면 보정을 영어+코드로 좁히는 논리가 섭니다.
  - 첫·끝 층의 언어 전용 전문가는 영어만 들어오면 쓰임이 줄 후보입니다.
  - 다만 끝 층에서 영어가 더 넓은 전문가 집합을 쓴다는 저자 문장 때문에 무료 삭제는 보장되지 않습니다.
- **REAP의 거의 무손실은 코드와 SWE에 한정됩니다.**
  - 같은 체크포인트에서 MMLU는 25%에 -6.3점, 50%에 -23.6점입니다. 다중 턴 도구는 절반 가까이 떨어집니다.
  - 영어 지식이 코드보다 먼저 깎입니다.
  - 보정 mix가 코드와 도구 중심이라 생긴 결과일 수 있습니다. 원인 분리는 논문에 없습니다.
- **K2 결과는 K3로 옮길 수 없습니다.**
  - K3는 896전문가 top-16, kimi_linear 하이브리드 어텐션, 잠재 MoE(routed_expert_hidden_size 3584)입니다. K2는 384전문가 top-8입니다.
  - K3 config는 sigmoid 라우터, moe_renormalize true, noaux_tc입니다.
  - 선택 편향 텐서도 같은 인덱스로 잘라야 한다는 점은 [19]가 bias를 슬라이스한 것과 구조가 같습니다. K3 모델링 코드는 읽지 않았습니다.
- **한국어는 고자원이고 큰 모델에서는 직접 추론이 이기는 경향입니다 [8].**
  - 캐스케이드의 이득은 가지치기가 한국어 용량을 이미 잃은 뒤에야 생깁니다.
  - 문화 과제 [7][9][10]와 도구 호출 [11]은 번역 쪽이 손해입니다.

## C. 사용자 계획에 의미

1. **크기:** 실측 구간은 K2와 Qwen3-Coder의 25%, 50% 두 점뿐입니다 [14].
   - K3에서 파일 감소는 24.5~49.0%입니다. 594 GB 기준 약 120~290 GB입니다 (B의 정밀도 가정 하).
   - 50%를 넘는 구간은 코드가 아닌 과제 근거가 없습니다. 번역 특화가 87.5%까지 가는 것은 번역만 평가한 결과입니다 [19].
2. **손실(K2 25%/50%) [14]:**
   - 코드와 SWE-Bench는 기준 ±0.03 이내입니다.
   - MMLU -6.3/-23.6점, MC 평균 -0.7/-13.7점, BFCL 종합 -3.1/-10.2점입니다.
   - 다중 턴 도구는 .355에서 .263/.164입니다.
   - 빈도 기준만 쓰면 25%에서 코드가 .631에서 .284로 무너집니다.
3. **영어+코드 보정은 코드를 지키고 영어 지식을 먼저 깎습니다.** 제외된 언어의 일반 성능은 측정한 출처가 없습니다. 가장 가까운 것은 비보정 고자원 언어가 보정 언어와 같은 곡선을 따른 번역 특화 결과 [19]입니다.
4. **캐스케이드 실패 모드:**
   - 출처 있음: 문화·한국어 과제 [7][9][10], 도구 호출에서 JSON과 도구 설명 번역 [11], 보호 구간 필요 [12], 스트리밍 번역의 계산 비용 [13].
   - 출처 없음: 코드, 표, 고유명사 손상률.
5. **번역의 이득은 약한 모델과 저자원 언어에 몰려 있습니다 [8][7].** 큰 모델의 고자원 언어에서는 직접 추론이 이깁니다.
6. **가장 싼 결정 실험:** K3에서 영어+코드로 REAP 점수를 구해 전문가 25%를 라우터 마스킹으로만 끄고, 영어 MMLU 부분집합과 코드 한 세트의 점수 차를 봅니다.
   - 예측은 코드 ±2점, MMLU -3~-10점입니다. K2 -6.3점이 기준이고 K3에서의 방향은 근거가 없습니다.
   - K2 결과는 W4A16 체크포인트와 코드·도구 중심 보정 mix에서 나왔습니다. MMLU 하락이 가지치기의 바닥이 아니라 보정 artefact일 수 있습니다.
7. **판정:** MMLU 손실 3점 이내면 50%와 캐스케이드 단계로 갑니다. 10점을 넘으면 비율을 낮추거나 접습니다. 번역 손실은 출처가 있으므로 이 한 측정이 나머지를 결정합니다.
